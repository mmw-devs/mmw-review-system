# H5 审核服务运行说明

本服务为 MMW 组织内成员提供飞书授权、本人任务审核及攻略站 Astro 文件导出，是后续统一使用的入口。服务器直接调用飞书官方 API，无需安装飞书 CLI；旧代码和[命令行说明](converter-cli.md)仅保留作历史兼容参考。

本文是当前运行能力、配置、审核操作和验证边界的说明来源。平台介绍与作者规范通过链接引用这些事实。攻略字段和关联约束仍以 [JSON 契约](strategy-json-format.md)及配套 Schema 为准。

**验证范围：已完成模拟 API 测试与本地浏览器操作验证，尚未完成真实飞书组织联调或生产部署。** 网页呈现的是可解析正文及两类问题清单，无法展示的内容应通过原文链接核对。此版本不包含独立二审、任务转交或公共任务池。

## 1. 环境和一次性配置

使用 Node.js 24 或以上，依赖其内置 HTTP、加密、SQLite 和 TypeScript 执行能力，不需要安装 npm 依赖。服务按单进程运行，不启用多实例或多进程共用数据库。

先由应用管理员在飞书开放平台配置自建网页应用：

- 设置网页入口、应用可用范围及对应可信域名。H5 走浏览器 OAuth 授权回调，不能只取得免登身份就跳过文档授权。
- 配置回调地址 `<REVIEW_ORIGIN>/auth/feishu/callback`，必须与服务配置一致。
- 开通用户身份下的文档、知识库读取和素材下载权限；需要刷新凭证时申请对应授权范围。
- 使用应用内用户标识 `open_id` 指定首位管理员；该用户首次登录时成为权限管理员，不自动获得审核角色，可在成员页面为自己勾选审核角色。

在项目根目录本地创建 `.env.local`，只在本机填写真实配置，不发到聊天、PR 或日志。文件已被 Git 忽略。以下仅是模板，尖括号需要替换：

```dotenv
FEISHU_APP_ID=<FEISHU_APP_ID>
FEISHU_APP_SECRET=<FEISHU_APP_SECRET>
FEISHU_TENANT_KEY=<ALLOWED_TENANT_KEY>
REVIEW_ADMIN_OPEN_ID=<INITIAL_ADMIN_OPEN_ID>
REVIEW_ORIGIN=https://<REVIEW_APP_DOMAIN>
REVIEW_ENCRYPTION_KEY=<BASE64_32_BYTE_RANDOM_KEY>
REVIEW_PORT=4325
REVIEW_DATA_DIR=data/review
FEISHU_USER_SCOPES="docx:document:readonly wiki:wiki:readonly drive:drive:readonly offline_access"
```

| 配置 | 含义 |
| --- | --- |
| `FEISHU_APP_ID`、`FEISHU_APP_SECRET` | 自建应用的标识及密钥；密钥仅用于服务端授权交换 |
| `FEISHU_TENANT_KEY` | 允许登录的飞书组织标识，不能用公司名称代替 |
| `REVIEW_ADMIN_OPEN_ID` | 首位权限管理员在此应用中的用户标识 |
| `REVIEW_ORIGIN` | 用户实际访问的完整站点源，不含路径和末尾斜杠；线上必须 HTTPS |
| `REVIEW_ENCRYPTION_KEY` | 32 字节随机密钥的 Base64 文本，用于加密本地飞书凭证；更换后原凭证无法解密，需重新授权 |
| `REVIEW_PORT` | 本机监听端口，默认 `4325` |
| `REVIEW_DATA_DIR` | 数据库与任务文件目录，不放到静态网站目录下；默认 `data/review` |
| `FEISHU_USER_SCOPES` | 空格分隔的用户授权范围；须在飞书后台开通，并按实际接口要求核对 |

上述 scope 是当前实现的候选组合，组织审批情况及最小权限范围需核实。素材下载存在不同授权范围与文档下载策略；正式启用前应由管理员根据官方接口及实测收窄并确认。应用获得接口权限仍不能访问用户没有权限的文档。

可在项目根目录执行以下命令，仅将随机加密密钥写入本地环境文件，不在终端打印；若已有该配置则拒绝重复追加：

```bash
node -e 'const fs=require("node:fs"),crypto=require("node:crypto"),p=".env.local";const s=fs.existsSync(p)?fs.readFileSync(p,"utf8"):"";if(/^REVIEW_ENCRYPTION_KEY=/m.test(s))throw Error("已存在加密密钥配置，请勿覆盖");fs.appendFileSync(p,"\nREVIEW_ENCRYPTION_KEY="+crypto.randomBytes(32).toString("base64")+"\n",{mode:384});console.log("已写入本地密钥配置，未显示密钥")'
```

备份数据库时单独保护环境文件；凭证加密密钥不能与数据库公开或放入 Git。初次安装时的管理员选择只生效一次，之后通过网页管理角色，不能仅修改环境变量来绕过既有管理员控制。

## 2. 启动与使用

完成本地配置后，在项目根目录执行：

```bash
node --env-file=.env.local src/review-server.ts
```

也可执行 `npm start`。服务只监听 `127.0.0.1`。正式使用需由既有 HTTPS 反向代理转发，并遵守仓库部署规则；已提供[部署模板](../deploy/README.md)，默认关闭且未应用到服务器。本地浏览器验证可将源设置为 `http://127.0.0.1:4325`；飞书端是否接受该回调须单独核实。

审核人员在页面中的操作顺序：

1. 使用飞书授权登录。普通成员初次登录后等待管理员授予审核角色。
2. 提交文档地址、副本 ID 和名称，选择标题识别模式，填写要求见下表。
3. 在“我的任务”刷新并打开任务，按“副本基本信息”、P1、P1.5、P2 等页面查看正文。顶部导航和上一页／下一页切换页面，地址保存当前任务与页面，支持刷新和浏览器前进后退。整篇问题清单始终可见，必要时打开飞书原文。
4. 查看“表现待确认”和“必须修正”两类问题。有必须修正项时不能审核通过或导出，可驳回或取消；回飞书修改后重新获取。没有必须修正项时，对副本基本信息和每个 P 分别通过或驳回。至少一个 P 通过后可以导出全文；有表现待确认项时还需明确确认全部预览表现可接受。仅副本基本信息通过不足以导出，其他页可保持待审核或驳回，页面明确列出未通过部分。
5. 点击“导出攻略站文件”生成产物，再点击下载入口，取得包含 `.astro` 页面、目录数据和引用图片的标准 tar 包。此包不含原始快照、授权凭证或内部审核记录，也不会自动发布网站。旧版已完成的 JSON 产物继续按原格式下载。

| 页面字段 | 填写要求 |
| --- | --- |
| 飞书文档地址 | 从浏览器复制完整 HTTPS 地址；接受 `feishu.cn` 或其子域下的 `/wiki/<TOKEN>`、`/docx/<TOKEN>` |
| 副本 ID | 网站约定的副本短 ID，例如网站路径 `/07/m5s` 对应 `m5s`；使用小写字母、数字及分隔用的短横线或下划线，不含游戏版本目录或完整路径 |
| 副本名称 | 填写副本的可读名称，最长 200 字符；文档自身标题由系统另行读取，保存到 `duty.title` |
| 标题模式 | 默认“兼容现有攻略”；明确按作者规范组织标题的文档选择“规范模板” |

程序检查副本 ID 格式，不查询网站目录确认它存在。测试 ID 的网站映射需在正式接入前核对。可选副本类型由任务接口接收，当前页面没有该输入项。

读取和权限核对可能需要等待，当前采用手动刷新，不提供持续进度推送。一次最多执行 4 个读取任务；单份正文上限为 24 MB／50,000 块。图片不设单张或单任务体积上限，但会占用服务器磁盘，需关注存储。任务列表只提供本人任务状态，不直接公开攻略标题；打开详情后才核对原文权限并显示内容。

“重新获取为新版本”创建一个关联的新任务，旧快照和决定保留，新任务所有页面重新审核，不自动沿用旧决定。旧任务的审核模式保留，重新获取后使用分 P 审核与 Astro 导出。当前实现不允许对已决定的同一快照反复改判；审核绑定导入时的固定快照，审批不要求当前 revision 与快照一致。需要审核新内容时重新获取为新任务，旧快照和决定保留。

## 3. 权限和授权失效

- 权限管理员可授予或撤销审核角色、设置管理员和停用成员，不能移除最后一位有效管理员。管理员身份不能查看他人正文。
- 每个任务只归发起人员使用。审核、预览、图片及下载接口均在服务端检查身份与归属；不支持接手。
- 首次获取任务详情、手动刷新、执行决定时，服务端重新检查原文正文的当前读取能力；图片直接从任务本地快照读取，导出时校验全部引用图片。同一任务内切换 P 使用浏览器内存快照，不重复请求详情或检查权限；已加载内容可能在外部撤销权限后继续显示，后续请求发现权限失效时清空。没有跨请求的长期权限成功缓存。
- 飞书不可用、角色撤销或凭证失效会阻止继续读取和导出，不自动切换为应用身份。
- “退出”使当前网页会话失效；“断开读取授权”清除本系统保存的用户凭证。后者不声称已撤销飞书侧授权，完整撤销应在飞书授权管理中完成。
- 用户凭证采用 AES-256-GCM 加密保存，授权码、令牌和原始上游错误不写入日志。当前不接收飞书授权撤销事件，实际调用失败后要求重新授权。

## 4. 存储与恢复

```text
REVIEW_DATA_DIR/
├── review.sqlite          # 成员、加密凭证、会话、任务和操作记录
└── runs/<TASK_ID>/
    ├── snapshot.json      # v2 原始文档块、内部节点、资源和完整性记录
    ├── assets/            # 已下载图片
    ├── candidate.json     # 结构化正文的便于查看副本
    ├── report.json        # 冻结的结构化正文、清单和诊断
    ├── export-plan.json   # 预检通过后的固定 Astro 源码与图片映射
    ├── pending-*          # 完整写入后准备发布的中间文件
    ├── strategy-site.tar  # 新任务的 Astro 页面和资源包
    └── strategy.json      # 旧版已完成任务可能保留的正式 JSON
```

数据库中的 `task` 是任务归属、状态、审核决定及校验哈希的唯一依据；`runs/<TASK_ID>/` 保存该记录引用的内容文件，不单独决定任务是否已审核或已导出。`report.json` 保存预览使用的固定转换结果；`candidate.json` 仅是便于查看的副本，修改它不会改变预览或导出。默认数据根目录是 `data/review/`，可由 `REVIEW_DATA_DIR` 指定。

新任务读取时转换一次并生成导出计划，后续查看、刷新、审核和导出都读取固定文件，不重新生成整篇 Astro。审核摘要 `digest` 绑定快照、选项、读取器与转换器版本、结构化正文；所有诊断统一保存在 `notices`（表现待确认）和 `blockers`（必须修正）中，不会加入审核摘要，但受 `reportHash` 保护。文件校验分工如下：

| 数据库字段 | 校验对象与作用 |
|---|---|
| `snapshotHash` | 原始快照完整性，仍用于原文访问权限检查 |
| `reportHash` | 冻结报告的实际字节，防止正文和诊断被手工改写 |
| `exportPlanHash` | 导出规则版本、审核摘要、完整源码字节及图片映射；生成产物时必须匹配 |
| `artifactHash` | 已完成正式产物的实际字节；下载不依赖当前导出器或报告 |

当前新任务采用 `astro-3`、存储记录版本 `3`。新报告只有 `notices` 与 `blockers` 两类问题；旧报告按原结构验证后仅在响应中映射，旧排除项归入必须修正。改变生成逻辑或导出校验规则必须升级 `ASTRO_EXPORT_VERSION`；版本门禁仅限制生成新产物。旧版本任务仍可查看、审核或取消，已完成产物继续校验权限和产物哈希后下载。未导出任务需重新获取并审核后使用新规则。即使误漏版本升级，已保存的导出计划也保证既有任务不会使用后来修改的生成逻辑。计划缺失或篡改返回状态冲突（409），不覆盖旧产物；查看详情不依赖计划。旧版报告按原摘要结构验证，不重新转换正文。

任务和图片路径由服务器生成。`data/` 不经静态路由暴露，文件下载始终经过权限检查。正式文件通过硬链接发布，不覆盖旧产物，因此底层文件系统需要支持硬链接。文件发布与 SQLite 提交不属于同一个原子事务；崩溃时可能留下已写入但未登记完成的文件。正式文件和对应中间文件可能共享内容，不应手工修改。

服务重启后，不自动续跑中断的读取。页面会提示重新获取；若文件已经生成但数据库状态未完成提交，系统拒绝覆盖，需创建新版本处理。当前未实现任务自动清理、磁盘配额或备份调度，正式上线前需确定保留期限和存储运维方案。将来清理任务应由同一受控流程按任务 ID 处理数据库记录与目录，并处理失败重试；不能只删一边，更不能删除整库，因为库中还包含成员、会话和加密凭证。备份也须同时覆盖数据库及其引用的任务文件。

### 4.1 攻略站导出包

新任务在任务目录中保存为 `strategy-site.tar`；浏览器下载名沿用 `strategy.tar`。旧版未完成任务须重新获取、重新审核，不能用原决定直接生成新格式；旧版已完成的 JSON 与 Astro 包继续按原产物下载。新任务的产物结构如下；`pages/` 不包含游戏版本目录，作者无需填写网站路径。

```text
strategy-site.tar
├── pages/
│   ├── index.astro       # 副本基本信息、攻略须知和战前准备
│   └── <PHASE_ID>.astro  # 各阶段正文
├── public/review-assets/<DUTY_ID>/
│   └── <IMAGE_FILE>      # 仅包含正文或横幅实际引用的本地图片
├── navigation.json      # 供网站维护者合并的目录数据
└── README.md            # 接入说明
```

网站维护者需确认目标路由，将 `pages/` 中的文件放入 `src/pages/<版本>/<副本短 ID>/`，将 `public/` 内容合并到网站静态资源目录，再按包内说明合并副本和阶段目录。生成页面通过目标站的 `import.meta.env.BASE_URL` 处理部署前缀，阶段时间 `base` 统一转换为数字秒；站点自身的导航和布局仍需在实际部署配置下验收。页面复用攻略站已有布局与组件；副本必须已经注册到站点的 `duties` 内容集合。`navigation.json` 供维护者合并阶段目录，网站分类、发布日期和游戏版本由维护者配置。

内部 JSON 继续作为预览和校验数据。导出层逐项生成允许的页面结构，文字按纯文本转义，不把飞书正文当作 Astro 表达式、HTML 或脚本执行。支持的格式及映射见[白名单](feishu-authoring-and-conversion.md#22-攻略站实际格式与组件白名单)。

## 5. API 读取与转换的能力边界

已接入 wiki/docx 解析、正文分页、父子引用完整性检查、读取前后版本核对和图片下载。保留基本文字样式、标题、列表、代码、简单普通表格及分栏。仅维护与攻略站输出契约衔接的白名单。未知组件、属性或无法解析的内容统一归为必须修正，不能经确认丢弃后导出。

H5 当前可读取的格式以[白名单](feishu-authoring-and-conversion.md#21-当前飞书作者要求)为准，旧 CLI 的历史调查不能作为网页已支持的证据。没有已验证映射的源格式统一返回必须修正，不单独维护组件黑名单。

文字颜色、已识别的图片裁剪／缩放、可解析普通表格的外观和代码语言等归为表现待确认。裁剪当前保留完整原图并明确提示未还原；未知变换、下载失败或结构缺失不能降级为表现问题。两类问题的判定、确认及修正流程见[转换规则](feishu-authoring-and-conversion.md#4-问题只分两类)。

有表现待确认项时，导出请求必须提交 `confirmPresentation: true`，确认当前整篇报告中的表现可接受；没有此类项目时无需确认。确认结果保存为 `presentationConfirmed`，导出审计同时记录操作者和 `reportHash`。接口不再接受丢弃作为导出授权，页面没有排除选项。必须修正项会禁止新任务审核通过和导出，但允许驳回、取消及查看可解析部分。

## 分 P 切分与审核边界

副本基本信息始终是首个审核页，包含副本名称、短 ID、可选类型、攻略须知和战前准备；这些内容不复制到每个 P。阶段页面只展示对应阶段正文，按原文顺序排列，不按编号重新排序。

`P1.5`、`P1.5阶段` 独立切分，内部标识为 `p1-5`，保留原始显示标题。规范模式的一级标题 `P1.5 · 阶段名称` 表示阶段，历史兼容模式的 `P1.5 · 机制名称` 表示该阶段下的机制，连续同阶段机制不会重复切分。转场不独立切分，留在当前 P；表格、分栏等容器内部标题不建立阶段边界。

审核接口沿用 `POST /api/tasks/:id/review`。新任务必须提交 `unitId`（`basic` 或阶段 ID）、`digest`、`snapshotHash`、`version`、`decision` 和 `comment`。服务端核对单元存在性、快照与规则摘要、任务版本，保存每页审核人、时间及意见，再汇总整篇状态。相同决定可重复提交；已决定的单元不能改判，正文修改后需重新获取。

导出的 Astro 包仍包含完整攻略，图片按引用去重；只通过一个 P 不会把其他 P 从产物中删去。分 P 审核记录仅存于内部任务，不进入攻略内容，也不改变内部 JSON Schema。

## 页面与服务端的操作契约

任务详情及审核、转换操作响应由服务端返回 `actions`，统一说明当前可审核的单元以及能否导出、取消和下载。`actions.review` 按 `unitId` 表示可提交审核决定，`actions.approve` 进一步控制是否可以通过；有必须修正项的新任务仍可驳回，但不能通过。旧任务使用 `whole`；`actions.export`、`actions.cancel`、`actions.download` 分别保存对应操作的结果。每项包含 `allowed`，不可操作时可提供 `reason`。这些动作信息按当前状态计算，不另行保存到数据库。页面根据结果展示操作和原因，不自行组合审核状态来决定业务资格；请求进行中、缓存过期等页面状态仍可临时禁用提交。

`actions` 表示生成响应时的判断。执行操作时，服务端仍重新核对身份、权限、任务版本和相关条件。错误响应包含供页面显示的中文 `error`、稳定的 `code` 和是否释放当前任务缓存的 `clearTask`；页面按这些字段处理错误，不从中文提示或 HTTP 状态猜测是否失去任务访问权限。


## 页面缓存与图片加载

当前任务的完整正文数据保存在浏览器内存中，各 P 的展示页面和图片在访问该页时创建。已访问页面复用，并保留意见草稿与阅读位置。同任务内切换 P 和浏览器前进后退不重新读取任务；刷新浏览器或切换任务重新读取。退出、断开授权以及请求检测到权限失效时释放缓存，不写入浏览器持久存储。

首次读取显示加载动画和等待提示，等待较久时提示仍在处理；手动刷新保留正文并显示更新状态。请求超时或失败提供重试入口。审核或转换成功后直接更新内存状态；状态冲突时重新读取，保留同一快照的意见草稿。刷新失败后仍可阅读缓存，但须刷新成功后才能再次提交。

图片显示失败独立于源图片拉取失败。失败时查询图片接口的具体错误，网络或临时服务异常最多自动重试两次，之后提供单图和本页失败图片重试。授权失效会清空任务，资源缺失或校验异常提示刷新或重新获取任务。图片显示失败不禁用“审核通过”，也不自动删除图片；源图片未取得则属于必须修正。

导出后仍可审核尚未决定的 P；完整攻略产物不因后续审核状态变化而重写。旧任务的审核与导出兼容边界见[存储与恢复](#4-存储与恢复)。
