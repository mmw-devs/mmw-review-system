# 飞书攻略撰写规范、攻略站白名单与转换规则

本文规定作者怎样组织文档，以及系统怎样将文档转换为[内部攻略 JSON](strategy-json-format.md)，再导出攻略站使用的 `.astro` 页面。只维护与攻略站衔接的格式白名单，不另列组件黑名单。第 2 节列出攻略站输出契约及当前飞书适配范围；未列入白名单或尚无已验证映射的内容统一归为“必须修正”。审核操作与当前能力以[服务运行说明](review-server.md)为准。[读取调查](investigations/2026-10-18-feishu-reading.md)与[历史转换节选](investigations/fixtures/feishu-read-probe.v0.1.json)仅提供历史可行性证据。

正文修改仍回飞书完成。审核单元与导出范围见[H5 使用流程](review-server.md#2-启动与使用)，作者不需要填写 JSON、英文锚点、游戏版本目录或机器标识。

## 1. 作者只需优先记住三条

1. **一级标题写阶段**，例如 `P1`、`P1.5`、`P2 · 小世界`。`P1.5` 是独立阶段；转场标题不另建阶段，内容留在当前 P。全文开头的“攻略须知”“战前准备”也用一级标题。
2. **二级标题写机制名称**，例如“无之膨胀”“众神之像2”。同一个机制再次出现，可以用“第二次”等文字区分，但不要求名称唯一。
3. **三级标题写说明或解法**：`机制说明`、`解法：黑洞基准`、`解法：BOSS基准`、`注意事项`。解法名称前保留“解法”二字，便于识别。

机制标题下面直接写正文也可以，默认作为机制说明；不强制补一个“机制说明”标题。没有备注就不用写备注，没有多个方案就不用写“解法1”。

四级及更低标题用于自由拆分步骤和小节，不要求统一命名。“机制时间轴”、伤害、站位优先级、宏等保留在正文中，不必拆成字段表。

推荐结构：

```text
文档标题：恩欧歼殛战攻略
一级：攻略须知                 ← 可选
一级：战前准备                 ← 可选
一级：P1
  二级：无之膨胀
    正文：机制效果……           ← 默认机制说明
    三级：解法：黑洞基准
      正文、图片、表格……
      四级：防护职能注意        ← 留在这套解法内
    三级：解法：BOSS基准
      正文、图片……
    三级：注意事项              ← 机制共同说明
  二级：核心熔毁
    ……
一级：P2 · 小世界
  ……
```

已有文档不必先全部重写。系统应按第 5 节兼容明确可识别的旧标题；无法确定时提示修正。

## 2. 少量内容约定

| 内容 | 建议写法 | 漏写时怎样处理 |
| --- | --- | --- |
| 解法是否 Beta | 在解法标题末尾写 `（Beta）` | 只有明确标记才写 `beta: true`；没写不推断已验证 |
| 推荐解法 | 在对应解法标题末尾写 `（推荐）`，可选 | 未标记则不设置 `defaultSolution`；多套都标记时提示冲突，不擅自选一套 |
| 职能提醒 | 用“防护职能注意”“治疗职能注意”“进攻职能注意”等文字 | 不根据颜色判断职能；无法确定时保留为普通说明 |
| 图片说明 | 直接在图片旁写说明文字 | 保留原位置，不自动把相邻段落或图片自动描述改成图注 |
| 宏、战术板代码 | 优先使用飞书代码块 | 普通段落中的代码仍保留原文，不擅自修复或压缩空格 |
| 表格 | 使用普通文档表格，不合并单元格；内容保持完整矩形 | 普通文档表格须完整可解析；超出当前适配范围时必须修正原文 |
| 其他第三方内容 | 优先使用可直接表达的文字、图片和表格 | 未适配内容统一归为必须修正，回飞书修改后重新获取 |

这些约定不要求作者将每张图片、每个提示框或每句话都打标签。

### 2.1 当前飞书作者要求

作者应按下表准备需要进入攻略站的正文。限制来自当前读取与转换实现。

| 内容 | 当前可用写法 | 避免的写法及处理 |
| --- | --- | --- |
| 强调 | 加粗、斜体、下划线、删除线，可组合 | 不用颜色或加粗代替阶段、机制与解法的标题级别 |
| 文字颜色 | 默认文字色，以及红、橙、黄、绿、蓝、紫、灰七种已适配前景色 | 不用文字背景色、高亮底色或未识别的颜色枚举；未知枚举或无法映射的样式归为必须修正 |
| 字号和字体 | 使用正常正文与标题样式 | 当前不读取任意字体、字号设置，不依赖它们表达必须保留的攻略含义 |
| 普通表格 | 非合并矩形表格；允许空单元格，非空单元格保留完整正文，允许文字、列表和可处理图片；可设置首行或首列表头 | 不使用合并单元格、嵌入电子表格、多维表格或复杂边框、底色表达机制关系；不要用空白占位模拟合并 |
| 表格宽度 | 保持内容简短；长表格可按机制拆分 | 不依赖精确像素列宽或行高；当前 H5 不保证还原原表列宽与外观 |
| 图片 | 直接插入可读取的图片，需要说明时在正文或明确图注中写出 | 已识别裁剪属性时展示完整原图并要求确认；不可接受时上传已裁剪图片。未知变换必须修正 |
| 分栏 | 使用飞书分栏，各列内容和顺序应明确，至少两列 | 不用跨栏重叠或空格排版表达图文对应关系；需在最终站点检查窄屏效果 |
| 宏与代码 | 使用代码块，保留原始空格与换行 | 不使用行内代码样式；代码只作为文字展示，不运行，不承诺语法高亮 |
| 提示与引用 | 普通引用、无自定义颜色／边框／图标的提示框 | 尚无映射的提示框样式必须修正；职能请用文字说明 |
| 链接 | 普通 HTTP(S) 链接；内部锚点须在目标页面存在 | 不使用脚本链接；普通链接不会自动变成视频播放器、附件预览或网站专用组件 |
| 白名单外的格式 | 回飞书改为上表支持的文字、图片或普通表格 | 统一提示无法解析并打回修改；不能确认丢弃后继续 |

当前颜色转换关系由[飞书读取器](../src/feishu-api.ts)固定定义：

| 飞书文字色 | 接口枚举 | 内部 JSON 色值 | Astro 输出 |
| --- | --- | --- | --- |
| 默认／清除颜色 | 未设置或 `0` | 不写 `style.color` | 继承网站正文颜色 |
| 红色 | `1` | `#d83931` | 保留此 RGB 值 |
| 橙色 | `2` | `#de7802` | 保留此 RGB 值 |
| 黄色 | `3` | `#dc9b04` | 保留此 RGB 值 |
| 绿色 | `4` | `#2ea121` | 保留此 RGB 值 |
| 蓝色 | `5` | `#245bdb` | 保留此 RGB 值 |
| 紫色 | `6` | `#6425d0` | 保留此 RGB 值 |
| 灰色 | `7` | `#8f959e` | 保留此 RGB 值 |

这些值是系统当前的色系映射，未证明与飞书各主题的实际像素颜色一致。Astro 导出保留 JSON 中的颜色，不再自动替换为网站预设的另一种色值。作者仍应同时写明“红色标记”“治疗职能”等文字，审核人员须核对颜色含义；浅色和深色主题下的可读性需要网站展示验收。

### 2.2 攻略站实际格式与组件白名单

攻略正文使用 **Astro 页面源码**。例如在线 [M5S P1](https://xivstrat.cn/07/m5s/p1) 对应 [`src/pages/07/m5s/p1.astro`](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/pages/07/m5s/p1.astro)。页面通过 `DutyStratLayout` 组合机制、解法、说明等组件，再由攻略站构建为 HTML。本节以仓库提交 `7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1` 为核对基准；站点升级后应重新核对接口。

上游没有一份限制全部攻略正文的 XML/XSD 字段表：`.astro` 可以写普通 HTML、受站点样式控制的内容以及程序组件。因此下表分别列出**已核实的原生组件接口**和**本转换器允许生成的子集**，不把本站组件的某个枚举解释成整个 Astro 语言的限制。审核系统不会接受作者填写任意 Astro、HTML、CSS 或脚本源码。

| 业务用途 | 攻略站组件及原生接口 | 本次转换映射 |
| --- | --- | --- |
| 副本首页 | `DutyLayout`：`dutyId`，默认内容插槽 | `duty` 的标题、名称、简称、类型、简介、横幅、视频链接、须知、准备内容写入 `pages/index.astro`；类型作为文字展示，不自动映射站点分类 |
| 阶段页面 | `DutyStratLayout`：`dutyId`、`base`，默认内容插槽 | 每个 `phase.id` 生成一页；标题和副标题保留；`base` 的分秒字符串转换为数字秒传入，缺省为 `0` |
| 机制分隔 | `SeparatorSection`：`id`、`title` 等 | `separator.id/title` |
| 机制、单解法、说明 | `MechanicSection`、`SolutionSection`、`NoteSection`：可选 `title`，其余属性向下传递 | `mechanic/solution/note` 的 ID、标题和正文；`beta`、`roles` 额外显示为明确文字，不虚构上游专用属性 |
| 普通正文 | `ContentSection`：可选 `class`，其余属性向下传递，默认插槽 | `content` 的 ID、标题和正文；标题放入正文，避免当成浏览器悬浮提示 |
| 多套解法 | `MultiSolutionSection`：`solutions: {id,title}[]`、`defaultSolution`；每套正文的插槽名为标题 | ID、标题都必须在同组唯一；JSON 默认方案 ID 转为上游要求的标题；未指定时仅默认显示第一项，不标记为推荐；启用客户端切换 |
| 折叠说明 | `CollapseSection`：`summary/details` 插槽；可选 `wider`、`color` | `collapse.summary/details` 分别进入插槽；外层保留 ID，标题放在摘要中；不自动配置 `wider/color` |

接口证据：[布局](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/layouts/DutyStratLayout.astro)、[普通正文](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/components/section/ContentSection.astro)、[解法](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/components/section/SolutionSection.astro)、[说明](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/components/section/NoteSection.astro)、[多解法](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/components/section/MultiSolutionSection.vue)、[折叠](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/components/section/CollapseSection.astro)。

攻略站还有 `AttackSection`、`EventSection`、角色图标、技能、伤害与状态图标等组件，示例页面实际使用了这些能力。本项目 JSON 没有完整对应的结构化战斗字段，本次不根据普通文字猜测伤害、读条、职能图标或时间轴；原文中的文字与普通表格仍按正文保留。

### 2.3 文字与正文输出白名单

下表是 JSON 到 Astro 的输出规则。它比当前 H5 读取能力更宽：例如 JSON 可以表达合并表格，但飞书读取器当前仍会阻止含未适配合并表格的任务导出。不能据此让作者使用第 2.1 节已标记不支持的来源格式。

| JSON 内容或字段 | 允许格式 | 输出规则与限制 |
| --- | --- | --- |
| `text.text`、`hard_break` | 普通文字、显式换行 | 输出转义文字和 `br`；尖括号、引号、花括号不执行为标签、属性或 Astro 表达式 |
| `style.bold/italic/underline/strike` | 布尔值，可组合 | 受控 `font-weight/font-style/text-decoration`，保留删除线与下划线组合 |
| `style.color/background_color` | 六位十六进制 `#RRGGBB`，大小写均可 | 受控 `color/background-color`，不接受任意 CSS、透明度或颜色名称；未设置时继承站点颜色 |
| `style.font_size_px` | 正数 | 输出像素字号；H5 当前没有任意字号来源适配；字体家族不在 JSON 契约内 |
| `href` | HTTP(S)、站内 `/路径`、当前页 `#锚点` | 拒绝凭据、控制字符、不安全协议；本页锚点经过关联校验，跨页地址仍需维护者核对 |
| `paragraph/heading` | 行内数组，可为空；标题级别 1–9 | 使用 `p`、`h1`–`h6`；原 7–9 级使用 `h6` 并保留 `aria-level`；空段落保留节点 |
| 段落／标题 `align/indent` | `left/center/right/justify`；非负整数缩进 | 受控对齐和按 `em` 表示的缩进；不承诺像素复刻飞书排版 |
| `image` | `src` 必填；可选 `alt/caption/width/height/align` | 原生 `figure/img/figcaption`；宽高为正整数，支持左右居中；最大宽度受容器限制；图注可带行内样式 |
| 本地／外部图片 | 本地限 `assets/` 下单层 PNG、JPG/JPEG、GIF、WebP、AVIF；或 HTTP(S) | 纯转换器返回资源映射；H5 实际下载仅接收已验证的 PNG/JPG/GIF/WebP。外部引用不下载，不声称已验证可访问 |
| `code` | `text` 原样；可选 `language/wrap` | `pre/code` 保留空格、制表符和换行；`wrap` 控制换行；语言仅作为标记，不新增语法高亮或执行功能 |
| `list` | `ordered`、非空 `items`；有序列表可带正整数 `start` | `ol/ul/li`，每项递归转换正文，保留嵌套和起始编号 |
| `table` | `rows[].cells[]`；可选正数 `column_widths_px[]` | `table/colgroup/tbody/tr/th/td`；宽表使用横向滚动容器，列宽参与布局 |
| 表格单元格 | 递归 `content`；正整数 `row_span/col_span`；布尔 `header`；十六进制 `background_color` | 保存跨度、表头和底色；拒绝孔洞、重叠、越界及列宽数量不符；不支持未定义的行高、边框或竖直对齐字段 |
| `columns` | 至少两列；每列正文，可选正数 `width_weight` | 保留列顺序与宽度权重；窄屏按原顺序纵向排列，不能依赖固定并排表达唯一含义 |
| `callout/quote` | 正文；提示框可带图标文字、背景色、边框色 | `aside/blockquote`；图标按纯文字或 emoji 展示，不解释为网站角色组件 |
| `divider` | 仅类型 | `hr` |

攻略站已有普通 HTML 表格的[实际源码示例](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/pages/07/zelenia/_mechanics/RoseBloodBloom_6.astro)。本转换器另外提供受控表格样式。

**网站预设色与飞书色是两份表。** 原生 [`Span.vue`](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/components/Span.vue) 的 `variant` 支持：

```text
default
red orange amber yellow lime green emerald teal cyan sky blue
indigo violet purple fuchsia pink rose slate gray zinc neutral stone
```

除 `default` 外，共 22 个预设色；浅色主题用对应 `text-*-600`，深色主题用 `text-*-400`。为保留内部 JSON 的颜色含义，转换器使用受限内联色值；这些文字不会自动随网站深色主题换色，也不会随精简阅读模式去色。作者无需填写 `variant`，维护者须检查最终主题对比度。

### 2.4 站点目录字段与接入要求

攻略正文与站点目录分开维护。上游 [`src/content.config.ts`](https://github.com/mogworks/xivstrat/blob/7b140bd18a71eb4a1304aa0c16ae7dbe41802fc1/src/content.config.ts) 对 `src/data/duties/` 的 JSON 定义了以下实际字段：

| 层级 | 必填字段与格式 | 可选字段与格式 |
| --- | --- | --- |
| 副本 | 字符串 `name/title/description/banner/date/href`；`type` 为 `raid/ultimate/trial`；`status` 为 `upcoming/live/new/done`；布尔 `indexAvailable`；数组 `phases` | 字符串 `short/spoilerFreeName/docLink/videoLink`；布尔 `spoilerFree`；对象 `navigationInfo`，其中可选 `name: string`、`parent: string[]` |
| `phases[]` | 字符串 `href/title/subtitle/name`；数组 `mechanics` | 当前无额外原生字段 |
| `mechanics[]` | 字符串 `href/name` | 当前无额外原生字段 |

上述元数据 Schema 对许多字段只检查字符串类型；地址、日期和横幅资源的显示效果需另行验证。内部 JSON 的副本分类是自由文本，接入时需映射到上游三个 `type` 枚举。

导出包的 `navigation.json` 是保留阶段、机制 ID 与名称等信息的**合并参考**。维护者需要确定真实版本目录，为阶段补齐完整 `href` 和缺省 `subtitle`，将机制 ID 作为锚点，并保留上表必填的既有副本信息。内部的 `id/base` 和多语言名称供维护者合并时参考。

页面放入实际 `src/pages/<版本>/<副本>/` 后，先移除 `import.meta.env.BASE_URL` 部署前缀，再使用实际 URL 推导布局需要的 `dutyId`；不把作者填写的短 ID 自动拼成 `/07/` 路由。`pages/index.astro` 与每个阶段文件都保留名称，图片复制到 `public/review-assets/<副本短ID>/`。生成页面中的站内链接和本地图片引用跟随 `BASE_URL`；目录参考中的链接仍需维护者按部署位置合并。发布前还需站点原有构建、导航与实际渲染验收。

## 3. 白名单的执行规则

攻略站 JSON Schema 与 Astro 导出映射定义可输出的字段、类型、值域及关联关系；飞书读取器只把已适配的源格式映射到这份契约。只有源内容可读取、映射已实现且生成结果通过校验时，才具备导出资格。

处理顺序为：保存原始快照 → 按白名单解析 → 校验正文、关联和资源 → 生成并冻结 Astro 计划 → 人工审核及表现确认 → 导出固定产物。

- 未知组件或字段直接进入“必须修正”，记录来源和原因，不补入一份黑名单。时间轴组件只是一个例子；普通文字或普通表格写的时间轴仍按其实际格式处理。
- 白名单外内容不能被默认忽略、替换为链接，或经“确认丢弃”后导出。系统展示可解析部分供定位；必须修正项全部解决后才可生成正式产物。
- 有明确映射、内容已取得且仅表现可能不同的项目进入“表现待确认”。读取失败、字段未知或结构缺失归为必须修正。
- 评论、编辑历史和授权数据属于协作／运行记录，始终不属于攻略正文；正文中的备注与注意事项正常保留。

当前 H5 的源格式范围见第 2.1 节。字段的机器校验见 [JSON Schema](../schemas/strategy.schema.json)，序列化实现见 [Astro 导出器](../src/astro-export.ts)。这三者应保持一致，不另维护“遇到某类组件才拒绝”的名单。

## 4. 问题只分两类

| 名称 | 内部字段 | 判断依据 | 操作者需要做什么 | 对流程的影响 |
|---|---|---|---|---|
| **表现待确认** | `notices` | 内容和引用可生成，存在已知且明确说明的显示差异 | 对照飞书与预览，确认全部表现可接受；不可接受则修改原文后重新获取 | 不判定为格式失败，可以审核；有此类项目时导出须明确确认 |
| **必须修正** | `blockers` | 无法解析、白名单不允许、内容／资源缺失、关系无效，或无法生成攻略站文件 | 根据来源定位回飞书修正，再重新获取并审核 | 新任务不能审核通过或导出；仍可预览已解析部分、驳回或取消 |

“警告”“排除项”“导出预检问题”不再作为独立分类。解析、JSON 校验、资源检查和 Astro 预检的问题都汇总到这两类，整篇清单在各 P 页面始终可见。原有“确认排除”入口已移除。

### 4.1 表现待确认的具体规则

| 可解析的项目 | 当前保留方式 | 必须说明的差异 |
|---|---|---|
| 已适配的文字颜色 | 映射到第 2.1 节色值并在 Astro 中保留 | 与飞书主题可能不同，需检查含义、对比度及深浅主题可读性 |
| 已识别的图片裁剪属性 | 下载并展示完整原图，裁剪数据留在内部快照 | **尚未还原裁剪**；预览和导出使用原图，不能宣称无损。不可接受时需上传已经裁剪好的图片 |
| 已适配的图片缩放与尺寸 | 保留原图与可表达尺寸 | 宽度、比例及图文对应关系需核对 |
| 可解析的普通表格 | 保留单元格内容、顺序和行列关系 | 列宽、边框及外观可能不同；内容或合并关系无法解析时属于必须修正 |
| 代码语言、标题折叠和兼容标题映射 | 保留代码文字、展开内容或已识别标题层级 | 不保证语法高亮、原折叠状态或推断的结构符合作者意图 |

只允许明确列出的表现差异。未知颜色枚举、未知图片变换或图片未下载成功都不属于此类。图片裁剪的确认表示审核人接受完整原图的表现。

### 4.2 必须修正的判定

统一检查以下条件，无需枚举被拒绝组件的名称：

1. 源组件、字段、样式或属性没有已验证的白名单映射。
2. 正文、图片或引用资源缺失，无法完整解析，或校验哈希不一致。
3. 阶段归属不明、重复进入同一阶段、空必填内容、失效锚点，或表格孔洞／重叠等结构关系错误。
4. 输出字段、值域、地址或路径不合法，或 Astro 生成无法满足组件接口。

能定位的内容问题显示来源块及修正建议。整篇读取失败、权限失效和网络错误仍按读取失败或重新授权处理，不能以保存不完整快照的方式绕过。

## 5. 审核与导出规则

新任务有必须修正项时，不提供“审核通过”或“导出攻略站文件”；审核人员可以填写意见并驳回，也可以取消转换。这里的“打回”表示校验不通过，不伪造人工审核决定。修改后使用“重新获取为新版本”，旧决定和旧表现确认不会自动沿用。

没有必须修正项时，沿用分 P 审核门槛：至少一个 P 人工通过即可导出全文，副本基本信息通过不计入；页面继续列出尚未通过的页面。

如果有表现待确认项，导出前需勾选“我已对照原文核对全部表现待确认项，确认预览表现可接受”。确认覆盖当前任务整篇清单，不能仅确认已通过的 P；没有此类项目时不显示勾选框。不默认勾选，关闭页面或超时不视为同意。服务端校验 `confirmPresentation`，保存确认结果、操作者和绑定的报告哈希；旧 `discard` 参数不提供任何绕过能力。

当前新任务使用 `astro-3`。读取时冻结报告和导出计划，审核摘要绑定快照、输入选项、读取／转换版本及正文。诊断文字不参与审核摘要，但受报告字节哈希保护；导出计划另有哈希，后续刷新和审核不会重新生成页面。已完成产物按原文件和哈希下载，不会随着转换代码改变。

旧版 JSON、`astro-1`、`astro-2` 任务保留原始报告与决定，显示时将旧提示映射为两类；旧排除项映射为必须修正。历史产物仍可下载，旧任务不能借旧决定生成新版产物。存储与兼容细节见[服务运行说明](review-server.md#4-存储与恢复)。

## 6. 白名单维护与验收

新增支持应同时核对：目标站字段或组件接口、飞书读取映射、JSON 字段及关联校验、Astro 序列化、问题分类、作者规范和回归用例。未知内容按统一规则失败，无需先登记名称。生成逻辑或校验规则变化须升级导出版本常量。

至少验证以下行为：未知组件（含未来新增类型）无法经确认绕过；颜色及已识别裁剪进入表现待确认；原图与裁剪差异明确可见；资源缺失和结构错误进入必须修正；确认绑定当前固定报告；无提示正文直接按审核条件导出；历史产物继续下载；浏览器中的分类、按钮和服务端判断一致。

静态 Schema 或语法编译检查不能替代目标站构建和实际渲染。真实飞书联调、站点布局、深浅主题和图片表现需单独验收。
