# 飞书攻略撰写规范与 JSON 转换规则（初版）

本文规定作者怎样组织文档，以及系统怎样将文档转换为[攻略 JSON](strategy-json-format.md)。命令行转换器已实现初版，运行方法和实际支持边界见[转换器使用说明](converter-cli.md)；审核页面尚未实现。本文的完整目标规则不等于所有来源类型均已适配。[读取调查](investigations/2026-10-18-feishu-reading.md)与[历史转换节选](investigations/fixtures/feishu-read-probe.v0.1.json)提供部分可行性证据。

初版只审核整篇文档，修改仍回飞书完成。作者不需要填写 JSON、英文锚点、游戏版本目录或机器标识。

## 1. 作者只需优先记住三条

1. **一级标题写阶段**，例如 `P1`、`P1.5`、`P2 · 小世界`。`P1.5` 是独立阶段；转场标题不另建阶段，内容留在当前 P。全文开头的“攻略须知”“战前准备”也用一级标题。
2. **二级标题写机制名称**，例如“无之膨胀”“众神之像2”。同一个机制再次出现，可以用“第二次”等文字区分，但不要求名称唯一。
3. **三级标题写说明或解法**：`机制说明`、`解法：黑洞基准`、`解法：BOSS基准`、`注意事项`。解法名称前保留“解法”二字，便于识别。

机制标题下面直接写正文也可以，默认作为机制说明；不强制补一个“机制说明”标题。没有备注就不用写备注，没有多个方案就不用写“解法1”。

四级及更低标题用于自由拆分步骤和小节，不要求统一命名。“机制时间轴”、伤害、站位优先级、宏等保留在正文中，不必拆成字段表。

推荐结构：

```text
文档标题：恩欧歼殛战攻略
一级：攻略须知                 ← 可选
一级：战前准备                 ← 可选
一级：P1
  二级：无之膨胀
    正文：机制效果……           ← 默认机制说明
    三级：解法：黑洞基准
      正文、图片、表格……
      四级：防护职能注意        ← 留在这套解法内
    三级：解法：BOSS基准
      正文、图片……
    三级：注意事项              ← 机制共同说明
  二级：核心熔毁
    ……
一级：P2 · 小世界
  ……
```

已有文档不必先全部重写。系统应按第 5 节兼容明确可识别的旧标题；无法确定时提示修正，而不是猜测。

## 2. 少量内容约定

| 内容 | 建议写法 | 漏写时怎样处理 |
| --- | --- | --- |
| 解法是否 Beta | 在解法标题末尾写 `（Beta）` | 只有明确标记才写 `beta: true`；没写不推断已验证 |
| 推荐解法 | 在对应解法标题末尾写 `（推荐）`，可选 | 未标记则不设置 `defaultSolution`；多套都标记时提示冲突，不擅自选一套 |
| 职能提醒 | 用“防护职能注意”“治疗职能注意”“进攻职能注意”等文字 | 不根据颜色判断职能；无法确定时保留为普通说明 |
| 图片说明 | 直接在图片旁写说明文字 | 保留原位置，不自动把相邻段落或图片自动描述改成图注 |
| 宏、战术板代码 | 优先使用飞书代码块 | 普通段落中的代码仍保留原文，不擅自修复或压缩空格 |
| 表格 | 简单内容用普通文档表格；已有电子表格可以继续使用 | 系统尝试补取电子表格；无法获取则给出明确缺失提示 |
| 时间轴组件与视频 | 若需要内容进入网页，作者可改写为普通文字／表格／图片 | 初版不转换这些组件；列出后由审核人员选择丢弃或放弃转换 |
| 其他第三方内容 | 优先使用可直接表达的文字、图片和表格 | 无法处理时进入同一选择流程，不能默认删除 |

这些约定不要求作者将每张图片、每个提示框或每句话都打标签。

## 3. 从飞书到 JSON 的处理顺序

```text
读取全文 → 保存原始快照 → 补取表格／组件／媒体
        → 识别目录与正文边界 → 转换正文块
        → 校验字段与引用 → 生成结果及问题清单
```

问题清单属于内部任务记录，不写进攻略内容文件。最少记录问题代码、源块定位、原因和处理建议，让审核人员能回到飞书对应位置。

### 3.1 快照一致性

读取时记录文档版本，以及补取资源各自的版本或摘要。电子表格有独立版本，不能把主文档版本当作所有嵌入资源的版本。

补取前后检查相关版本；若发生变化，提示本次快照不一致，重新获取相关内容或重新发起整篇审核。对没有版本号的资源，至少保存实际读取结果及摘要，并明确一致性限制。不要声称跨文档、表格和媒体取得了原子快照。

审核通过后使用已保存的内容和资源生成产物，不再悄悄读取修改后的飞书正文替换它。

### 3.2 副本基本信息

- 文档标题可作为 `duty.title`；副本名称、短 ID 和类型从任务配置或明确的文档信息取得，不推断英文 ID。
- `duty.id` 例如 `m5s`，不包含 `07` 游戏版本目录。网站侧决定路由。
- 原文开头的引言及“攻略须知”写入 `duty.introduction`；“战前准备”及其子内容写入 `duty.preparation`。
- 封面不自动取第一张图片；未指定的图片保留原位置。视频块列入不支持转换清单，不自动转换成主视频链接；普通外部视频链接仍按链接保留。
- 文档前言与准备内容交错、或结束部分存在无法归入任何阶段的全局内容时，先保留源顺序并报告结构歧义，不为适配当前三部分结构而静默重排。当前格式尚不表示任意全局章节的交错顺序。

### 3.3 标题和正文边界

先在用于识别的副本上规范空格、全角数字／标点和大小写；输出仍保留作者原始文字。不能对正文整体做 trim 或替换。

按下列优先级识别：

1. 判断是否为已知的全局标题、阶段标题、组合阶段机制标题。
2. 在已确定的阶段中，结合标题级别识别机制边界。
3. 在机制或阶段中，识别“机制说明”“解法”“注意事项”等用途。
4. 无法确定的标题作为原级别的小标题留在当前正文，并报告疑点。

为避免误判旧文档，转换任务在内部区分“规范模板”和“历史兼容”两种识别配置，不增加攻略 JSON 字段。只有明确采用本规范的文档才按二级标题直接建立机制；历史文档默认采用兼容配置，优先识别明确阶段前缀和已知用途标签。比如妖星正文中的二级“真假火雷”可能是现有机制的小节，不能仅凭二级标题自动升级为独立机制；归属不明确时保留小标题并提示。不能因为文档开头有一两个规范标题，就认定整篇符合规范。

仅在文档顶层标题块上建立阶段和机制边界。分栏、表格、提示框内的标题保留在容器内部，不因为遇到“P1”字样就拆开整张表。

推荐规范下：

- 一级阶段标题持续到下一个阶段或明确全局标题。
- 二级机制标题输出 `separator`，并生成对应机制导航项。
- 机制标题后、三级用途标题前的正文输出 `mechanic`。
- 阶段开头尚无机制时，正文可以输出 `content`；可以有阶段级解法，不编造机制名称。
- 三级用途标题持续到同级或更高的下一个标题。四级及以下标题留在该区块内；明确使用旧格式的七级解法标题按兼容规则处理。
- 下一阶段、下一机制或下一套解法出现时，必须关闭上一套解法，不能因标题级别异常把后续全文吞进一个方案。

### 3.4 多套解法与局部备注

同一机制中连续出现的多个同级解法，且期间没有无法确定归属的区块时，组合为 `multi_solution.solutions[]`。每套解法的图片、列表、小标题和内部提示框留在该方案的 `content` 中。

例如解法 A 内四级标题“治疗职能注意”仍属于 A；三级“注意事项”表示与解法同级的共同说明，结束当前方案分组。

旧文档中解法之间夹有归属不明确的备注时，先保留多个独立 `solution` 和原顺序，报告归属待确认，不强行组合为切换选项。

“推荐”只在当前解法分组内解析；存在唯一明确推荐时设置 `defaultSolution`。推荐标记有冲突时省略默认值并提示，标题原文仍保留。不会把“第一套”默认解释为“推荐”。

### 3.5 稳定标识

内部维护“源文档标识 + 源块标识 → 输出 ID”的映射，原块仅改标题或移动时复用输出 ID；同名机制在不同位置仍生成不同 ID。多解法中的每个方案以自身源标题块定位。

不要用数组序号作为长期身份，也不要求作者维护英文锚点。删除后重新创建的飞书块可能有新身份，需要记录为新块，不只凭同名认作原块。映射信息属于内部快照，不增加攻略 JSON 字段。

## 4. 内容块转换规则

| 飞书内容 | JSON 输出 | 不能悄悄做的事 |
| --- | --- | --- |
| 段落、标题、换行 | `paragraph`、`heading`、`text`、`hard_break` | 删除空段落、把删除线内容当成正常文字 |
| 颜色、强调、链接 | `style` 和 `href`；RGB 转六位十六进制 | 限制为旧项目少量颜色、无提示丢失未知格式 |
| 图片 | 下载后写 `image.src` 相对路径，保留顺序与可表达尺寸 | 把自动图片描述当作作者图注；用下载原图冒充已正确处理裁剪 |
| 分栏 | `columns`，按列保存；`width-ratio` 转 `width_weight` | 拍平图片与文字关系；只支持两列而截掉其余列 |
| 普通表格 | `table`，单元格递归转换，保留行列与跨度 | 将单元格中的图片丢失；凭颜色自动认定表头 |
| 嵌入电子表格 | 补取范围、值、样式和布局，转 `table` | 将未取到的数据当成空白；忽略截断或隐藏数据边界 |
| 提示框、引用、列表 | `callout`、`quote`、`list` | 根据底色推断解法状态或职能 |
| 代码块 | `code.text` 原样保存 | trim、重排换行或自动改写战术板代码 |
| 已识别时间轴组件 | 不转入正文，列入待处理清单 | 因为可解析就默认降级为列表 |
| 视频 | 不下载、不转入产物，列入待处理清单 | 自动改成链接以绕过选择 |
| 音频、附件 | 初版不下载、不转入产物，列入清单 | 自动改成链接或用附件预览替代正文 |
| 同步块、引用正文 | 完整取得正文后按普通内容递归转换；否则列入清单 | 将引用标识当作正文；承诺持续同步 |
| 其他第三方组件、嵌入网页 | 初版列入清单 | 执行组件代码或默认改成链接 |
| 画板、流程图、思维导图 | 未验证能完整转成图片前列入清单 | 只提取文字而丢失节点和连线关系 |
| 看板、仪表盘、嵌入图表 | 初版列入清单；简单单元格表格仍可转换 | 用普通表格冒充已保留整个视图 |
| 评论、编辑历史 | 属于协作记录，默认不进入攻略正文 | 将正文中的作者备注误判为评论而排除 |
| 未知内容 | 审核预检中显示源位置和内部占位，等待选择 | 自动删除、将占位写入最终攻略、执行插件代码 |

### 4.1 电子表格补取

1. 从文档块取得表格 token 和工作表 ID，只读取文档引用的工作表／范围，不遍历无关工作表。
2. 先读取布局范围、合并信息、列宽及隐藏行列，再读取单元格。若嵌入范围不明，先调查，不把整本表格当成引用内容。
3. 检查 `has_more`、`truncated`、`actual_range`，使用返回的 `row_indices`、`col_indices` 定位；不能按返回数组下标猜原位置。
4. 分批读取时保存覆盖范围，并检查版本；不齐全或版本不一致就报告，不当完整表格输出。
5. 初版建议输出读取到的显示内容，不保留可执行公式、不在本地重算。样本没有公式，公式显示值的读取方式仍需另外验证；没有显示值不能自行计算。
6. 有隐藏行列、筛选或图表等未验证内容时，保留原始数据并报告，待明确“作者可见内容”的范围，不把隐藏草稿悄悄加入正式产物。

当前 Schema 可表达文字、颜色、字号、列宽和跨度，但没有单元格竖直对齐、行高、边框等字段。读取到这些属性时记录表现差异；是否扩展 Schema 或接受差异，待实际渲染后决定。

### 4.2 时间轴组件不纳入初版转换

读取调查证明组件 `blk_6358a421bca0001c22536e4c` 可以返回时间轴条目，但可解析不等于适合当前网站格式。初版将其标记为“不适用”，不转换成列表、表格或其他正文。

普通段落、普通表格或图片形式的时间轴仍走对应内容规则，不因为标题含“时间轴”就排除。识别依据是源块／组件类型，不能只凭关键词删除正文。

### 4.3 图片和其他资源

建议下载到当前审核快照的资源目录，核对文件签名和大小，计算摘要，再写入相对路径。相同文件可去重，但每个正文位置及各自裁剪信息必须独立保留。

图片裁剪属性已在样本中发现。当前 Schema 尚不保存裁剪区域，需进一步确认其坐标含义和渲染方式；在能正确还原裁剪前，将相关图片列入不支持转换清单，由审核人员选择丢弃或取消，不用整张原图替代。裁剪数据保留在内部快照，当前不新增未经验证的裁剪字段。此项不是作者标题规范能够解决的问题。

视频、音频和附件块初版不下载，按源块列入不支持转换清单。图片获取失败等能够准确定位的内容同样提示审核人员。不能写一个不存在的本地地址冒充成功。

## 5. 人工疏漏的补偿

本节是目标补偿规则，不代表当前程序已覆盖所有疏漏。补偿规则分为三种结果：明确可识别则继续转换并提示；内容可保留但归属有疑问则输出待确认草案；无法取得内容则输出缺失说明。它们是转换诊断，不代替人工审核结论。

当前命令行能兼容部分明确的旧标题，并阻断已识别的结构错误；普通段落中的解法标签仍保留为正文，疑似方案提示尚未实现。空机制标题可能保留在导航，连续末尾图组也不会自动判断归属。现有标题兼容分支不保证每次都报告级别偏差。核对时须结合[当前限制](converter-cli.md#5-支持范围与已知限制)。

| 情况 | 处理规则 |
| --- | --- |
| `P1阶段` 写成二级标题 | 阶段命名明确时识别为阶段，报告标题级别偏差 |
| `P1 · 众神之像2` 写成一级标题，没有单独 P1 | 从明确前缀建立 P1，上述标题作为机制；保留全文原顺序，提示使用了组合标题兼容规则 |
| `解法1（黑洞基准）` 写成七级标题 | 在明确机制上下文中识别解法，不要求批量修改旧文档 |
| `传送阵·解法1` | 在标题中识别明确的解法标签，保留完整标题，不把正文中提到“解法”也当成边界 |
| “解法”是普通加粗段落 | 提示疑似标题，保留原段落；初版不自动升级所有加粗文字 |
| 机制标题忘设级别或漏写 | 保留原块与顺序，报告疑似机制边界；不悄悄并入上一机制后宣称识别正确 |
| 缺少机制说明标题 | 机制名称后的正文默认 `mechanic` |
| 一个阶段直接写解法，没有机制标题 | 保留阶段级 `solution`，目录可为空，不编造机制 |
| 同名机制出现多次 | 分配不同 ID，不去重、不合并 |
| 正文提到“同P1”“解法见前文” | 保留普通文字，不当作新阶段或新方案 |
| 标题包含 `[分P阶段]`、`[机制名]` | 识别为模板占位，结束已明确的正文边界后标记归属待确认，不默认归入上一阶段 |
| 阶段前缀冲突、阶段顺序返回之前阶段 | 保留原顺序并报告；当前每阶段一份正文的结构不能靠重排掩盖这种冲突 |
| 无法确定内容属于前言、准备还是阶段 | 原始快照完整保存；结构化结果标为待确认，不丢弃或随意归类 |

当前纠正入口是飞书原文；命令行只提供历史兼容与规范模板两种识别方式，尚不支持逐块配置映射。未来页面可展示问题与源位置，让作者修改后重新获取、重新审核，不在审核页改写正文。

不把标题歧义自动等同于“内容应丢弃”。能够明确定位的不支持内容按第 6 节选择；无法确定阶段等全局结构错误仍需修正文档或转换配置，不能用“丢弃”掩盖整篇解析失败。其他表现差异与最终完整性门槛仍待确定。

## 6. 不支持内容的选择流程

“当前不支持转换的内容”分为：可读取但初版不适用（时间轴组件、视频、音频、附件块及其他未适配组件），以及无法读取／解析／输出的内容。它们共用选择流程，但提示原因应区分，不把可读组件误报为解析失败。

### 6.1 分类与提示

| 分类 | 范围与处理 |
| --- | --- |
| 当前不支持转换 | 时间轴组件、视频、音频、附件块、其他第三方组件、嵌入网页、看板、仪表盘及嵌入图表。进入丢弃／取消清单 |
| 尚不满足转换条件 | 未验证可完整转为图片的画板／流程图／思维导图、不能正确还原裁剪的图片、未完整获取正文的同步块／引用正文，以及能够准确定位的读取失败或未知内容。进入同一清单，区分原因 |
| 可转换，展示效果需检查 | 文字、图片、普通表格、分栏等内容和关系能够保留，仅字号、边框等外观可能变化。显示位置与差异，不自动加入丢弃清单 |
| 默认不导出的协作记录 | 评论、编辑历史等；不属于攻略正文，无需每次选择。正文内的作者备注与注意事项仍正常转换 |

颜色、位置、裁剪等如果承担机制区分或图文对应含义，无法保留时必须归入不支持清单，不能只报告外观变化。不能确定是否影响含义时，阻止正式导出并要求核对；不默认认为差异无害。

同步块成功展开后仅保存审核快照中的正文，不保存持续同步能力；内部记录引用来源与获取版本。递归内容仍逐块检查，出现循环引用或无法完整展开时报告明确范围。简单电子表格不因属于外部资源就整体排除；仅当缺失范围能独立定位且不破坏其余表格关系时，才可单独排除，否则列出受影响的整个表格。

以上为初版目标范围，不代表已在两份攻略中发现所有类型，也不代表命令行已适配全部来源。原文已有的普通链接可以保留，但不自动把不支持组件替换成链接。

### 6.2 审核人员的选择

1. **先列清单。** 显示类型、数量、所在阶段／机制、源块定位或链接、名称／摘要及原因。只列明可以准确定位的范围，避免误删附近正文。
2. **等待明确选择。** 提供“丢弃清单内内容，只转换其他内容”和“放弃本次 JSON 转换”。不默认勾选丢弃，未选择、关闭提示或超时都不视为同意；任务保持等待，不生成最终文件。
3. **选择丢弃。** 只排除已列出且已确认的源块及其明确包含的内容，保持其他内容顺序。丢弃作用于输出，不改飞书原文，原始快照继续保留。内部记录快照、清单、操作者和选择时间，攻略 JSON 不增加这些字段。
4. **重新校验。** 如需连带删除空区块、导航或默认解法，预先说明这些影响；若发现清单外的新内容需要排除，则重新确认。禁止留下空的必填正文、失效锚点或不存在的资源引用。排除后没有足够内容形成合法攻略时，不生成最终 JSON，并说明原因。
5. **选择放弃。** 结束本次转换，不生成或替换最终 JSON，不覆盖此前成功产物。保留内部快照和任务记录；不自动将人工审核结果改成驳回。

选择绑定当前快照和具体清单，不是对同一文档未来所有未知内容的一次性授权。补取时出现新的失败、内容范围改变或重新拉取文档后，原选择不自动覆盖新清单。

正文块之外的整体读取失败、无法定位的结构损坏等不能通过丢弃一个占位来绕过，应明确转换无法继续。网络失败可重试，但不得把重试失败默认为用户同意丢弃。

最终文件只包含保留的可转换内容，不输出 `embed` 或任何 `media` 块。结果显示“已转换，按确认清单排除部分内容”并可查看清单，不称为完整保留全文。Schema 只能限制输出形状，不能验证人是否真的作出了选择；授权检查必须由任务流程执行。

## 7. 实施验收建议

转换器落地时至少核验：

- 每个源块都有去向：正文、导航标题、内部批注／元数据，或明确确认的排除项；不存在静默丢块。
- 未选择不生成文件、放弃不覆盖旧产物、清单变化重新确认；只有被列出的内容才可排除。
- 目录与正文锚点一致，重复名称、错误层级和多套解法不会造成内容串段。
- 表格读取不截断，跨批次版本一致，嵌入资源与审核快照关联。
- 原文可见文字、删除线、图片顺序、表格和分栏逐项对照；Schema 校验不能替代实际渲染检查。
- 表现差异、未下载资源、模板占位和歧义都有源位置及处理建议；仅外观差异与无法保留含义分开提示。
- 裁剪未还原的图片不被原图替代；同步块不完整或循环引用不得冒充已展开；评论与正文备注正确区分。

先用两份现有攻略验证兼容规则，再用符合推荐标题的短文档验证标准流程。不要先要求作者为尚未验证的转换器大规模改写历史文档。
