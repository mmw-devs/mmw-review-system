# 飞书攻略读取能力调查

> 2026-10-19 范围决定：初版不转换时间轴组件或视频。下文保留当时的读取事实与试验，不代表当前转换策略；列表转换样例仅作历史验证。当前处理见[转换规则](../feishu-authoring-and-conversion.md#6-不支持内容的选择流程)。

调查时间：2026-10-18（Asia/Shanghai）。目标是验证文档正文之外的表格、第三方组件和图片能否读取，并为 JSON 转换规则提供依据。

## 1. 范围和身份

通过本机已配置的飞书 CLI，以 `user` 身份只读访问用户提供的两份攻略。未修改飞书文档、权限或登录配置。结果仅证明当前用户授权下的读取能力，不证明未来服务器应用或机器人身份拥有相同权限。

| 文档 | 本次返回版本 | 全文结构 |
| --- | --- | --- |
| [恩欧歼殛战草稿](https://mmw-ffxiv.feishu.cn/wiki/ILFIward8isSn3kTjjJcZgLnn8f) | 4007 | 77 个图片块、19 组分栏、1 个嵌入表格、1 个组件占位 |
| [妖星乱舞绝境战草稿](https://mmw-ffxiv.feishu.cn/wiki/A0NfwHceXiiHgxkoKtQcP0gQn2c) | 29623 | 296 个图片块、78 组分栏、20 个普通表格、1 个嵌入表格、9 个组件占位、3 个视频引用 |

使用 `docs +fetch --detail full` 获取结构；对嵌入表格使用 `sheets +sheet-info` 和 `sheets +cells-get`；对组件使用官方块内容 GET API；图片使用 `docs +media-download`。

## 2. 实际结果

### 2.1 嵌入电子表格：两份均读取成功

| 样本 | 布局返回范围 | 单元格读取请求 | 实际返回 | 表格版本 |
| --- | --- | --- | --- | --- |
| 恩欧战前准备表 | `A1:B5` | `A1:H20` | 10 个单元格 | 6 |
| 妖星战前准备表 | `A1:B6` | `A1:H20` | 12 个单元格 | 1 |

两次结果均为 `has_more: false`、`truncated: false`；实际范围覆盖布局报告范围，布局版本与内容版本一致。返回了文本值、字体颜色、背景色、字号和列宽，也返回了行高、边框和竖直对齐等属性。

两份表格均无合并单元格、隐藏行列；样本没有公式。因而不能据此宣称已经验证公式结果、复杂合并、筛选、隐藏区域或嵌入图表的转换。

结论：这些具体嵌入表格可以补取成普通 JSON 表格，不需要永久停留在占位状态。

### 2.2 第三方占位：十个均取得同类时间轴数据

全文快捷读取只显示 `readonly-block type="isv"`。进一步读取原始块时，10 个块均返回 `block_type: 40` 和 `add_ons.record`，组件类型均为 `blk_6358a421bca0001c22536e4c`。

其记录包含 `items[]`，条目有 `time`、`title`、`text`；还包含显示开关 `contentShow` 和排列方式 `mode`。

| 样本 | 内容情况 |
| --- | --- |
| 恩欧的 1 个组件 | 5 个全空条目 |
| 妖星的 6 个已填组件 | 分别 10、12、7、19、9、30 个条目，共 87 个 |
| 妖星的 3 个模板组件 | 每个 3 个条目，仍含 `[机制A]` 等模板文字 |

本次全部显示开关为 true；排列方式为横向交错或纵向排列。时间仅部分条目有值。

结论：可以针对该组件类型设计专用适配器，保存为按顺序排列的普通正文列表。不能把该结论推广到所有第三方组件，也未验证交互或与飞书画面完全一致。

### 2.3 图片：抽样下载成功

从恩欧文档下载了 1 张图片：PNG，1,355,654 字节，文件头确认尺寸为 1280×720，SHA-256 为 `a59101e0910cd8d9dc37c47726a809c314331539e209748c9ca2c11b3702058b`。

Windows 版 CLI 拒绝 WSL 网络命名空间输出路径；切换到已授权的 Windows 本地目录，并按 CLI 允许的当前目录相对路径保存后成功。该结果说明最初的问题是本地输出路径限制，而非图片访问权限失败。

只抽样验证了 1 张，没有下载全部 373 个图片块，也没有逐张目视检查。

另在妖星的表格配图中发现 `crop` 和 `scale` 属性。现有 JSON Schema 未表达裁剪信息；坐标含义、处理方式与渲染效果尚需验证，不能将原图下载成功视为显示效果完整保留。

### 2.4 视频与其他内容：仅检查元数据

妖星文档有 3 个 `video/mp4` 附件，报告大小分别为 142,342,794、182,961,138、199,966,316 字节，合计 525,270,248 字节。本次未下载，未测试播放。

分栏实际包含 2–5 列，不可按固定两列实现。普通表格中存在图片，因此表格单元格必须支持嵌套正文，而非仅字符串。

## 3. 转换验证样例

[feishu-read-sample.v0.1.json](fixtures/feishu-read-probe.v0.1.json)包含从妖星实际读取的 6×2 战前准备表，以及“众神之像2”的 12 条时间轴。

- 验证样例通过当前 JSON Schema。
- 检查了 12 个单元格文本值与源值完全一致、12 条时间轴内容与顺序保留。
- 保留了可表达的颜色、字号、粗体、背景和列宽。
- 未保留表格边框、行高及竖直对齐；时间轴改为列表，未复刻原组件布局。
- 副本 ID、区块 ID 为演示值；章节归属依据已读取标题选定，不是完整自动标题识别结果。

此样例验证数据适配的可行性，不是完整攻略、通用转换器或浏览器渲染验收。

## 4. 对设计的影响

1. 嵌入表格和该时间轴组件应尝试补取，不应一律标为不可读。
2. 读取与转换分开报告：有些样式已取得，但当前输出结构还不能表达。
3. 使用少量标题规范加兼容识别，不要求作者把每个正文元素都变成表单字段。
4. 将未知组件、裁剪图片、隐藏或复杂表格内容和大视频保留为明确待验证项。
5. 文档、表格和资源有不同版本／获取时点，服务端实现需要验证快照一致性和实际授权。

具体规则见[飞书攻略撰写规范与 JSON 转换规则](../feishu-authoring-and-conversion.md)。最终完整性门槛仍未确定。
