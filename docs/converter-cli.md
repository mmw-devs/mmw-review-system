# 飞书攻略命令行转换器

转换器接收飞书文档地址，读取正文、图片和支持的嵌入表格，生成符合当前契约的 JSON。它不执行人工审核通过／驳回，也不发布网站；“转换完成”只表示本次文件生成完成。

## 1. 运行条件与输入

需要 Node.js 24 或以上，以及已安装并登录的飞书 CLI。当前项目无第三方运行依赖，不需要运行安装命令。默认借助 CLI 的当前用户身份只读访问飞书，不修改原文，也不读取或输出登录凭据。

在项目根目录执行，替换尖括号中的值：

```bash
node src/cli.ts "<FEISHU_DOCUMENT_URL>" --duty-id "<DUTY_ID>" --duty-name "<DUTY_NAME>"
```

三个占位符的填写方式如下。替换时连同 `<`、`>` 一起去掉，保留外面的双引号；不要把占位符原样输入。

| 占位符 | 含义和填写来源 | 示例 |
| --- | --- | --- |
| `<FEISHU_DOCUMENT_URL>` | 要转换的飞书攻略文档完整链接，从浏览器地址栏复制；程序用它读取正文 | `https://mmw-ffxiv.feishu.cn/wiki/ILFIward8isSn3kTjjJcZgLnn8f` |
| `<DUTY_ID>` | 副本短标识，保存为 `duty.id`。对接网站时使用网站约定的 ID；它不是链接末尾的飞书文档标识，也不是 JSON 文件名 | 网站地址 `/07/m5s` 对应 `m5s`，不要填 `07` 或 `/07/m5s`；本地测试可用 `demo-enou` |
| `<DUTY_NAME>` | 副本的可读名称，保存为 `duty.name`，由操作者明确填写 | `恩欧歼殛战` |

例如转换恩欧攻略，在项目根目录执行：

```bash
node src/cli.ts "https://mmw-ffxiv.feishu.cn/wiki/ILFIward8isSn3kTjjJcZgLnn8f" --duty-id "demo-enou" --duty-name "恩欧歼殛战"
```

这里的 `demo-enou` 是本地测试 ID，不代表网站已采用这个 ID。若暂时不知道正式 ID，可以先使用明确的测试标识；正式接入网站前应确认映射。程序只检查 ID 格式，不会查询网站目录确认它是否存在。

`DUTY_NAME` 与文档标题是两个字段：例如副本名称为“恩欧歼殛战”，飞书文档标题可以是“【MMW攻略组】恩欧歼殛战文档攻略 草稿版”。后者由程序读取并保存为 `duty.title`，不需要另填参数。

当前仅接受 HTTPS、`feishu.cn` 或其子域下的 `/wiki/<TOKEN>`、`/docx/<TOKEN>` 地址。副本 ID 使用小写字母、数字及分隔用的短横线或下划线，不含路径，例如 `m5s`；副本名称由操作者输入。类型可选，不从标题猜测英文 ID，不增加游戏版本目录。

默认从系统命令路径寻找 `lark-cli`。Windows 下也会检查当前用户 npm 全局目录中的官方 CLI `run.js`；找不到时可用 `--cli-path` 明确指定现有安装。

### Windows 与 WSL

在 Windows 本地项目目录的 PowerShell 中可使用上面的 `node` 命令；若使用 npm 命令且 `npm.ps1` 被拦截，改用 `npm.cmd`，无需修改执行策略。

若项目在 WSL、Node 和飞书 CLI 在 Windows，需从 WSL 项目目录执行，并提供已存在的 Windows 本地图片临时目录：

```bash
node.exe "$(wslpath -w "$PWD/src/cli.ts")" "<FEISHU_DOCUMENT_URL>" --duty-id "<DUTY_ID>" --duty-name "<DUTY_NAME>" --media-workdir '<WINDOWS_LOCAL_DIR>'
```

`<WINDOWS_LOCAL_DIR>` 使用 Windows 路径，例如操作者自己的本地临时目录。Windows CLI 的下载路径限制可能拒绝 WSL 网络路径；此参数只改变临时图片下载位置，攻略任务及最终图片仍保存在输出目录。使用同一系统内的本地项目时通常可省略。

## 2. 预检与确认

每次获取建立独立的 `conversion-<RUN_ID>` 目录。程序显示文档读取和资源检查进度，然后给出不支持内容、一般提示和阻断问题的数量。

- **没有不支持内容和阻断问题**：正常模式直接生成 `strategy.json`，即使没有交互终端也可完成。
- **有不支持内容**：列出来源和原因，交互终端可输入 `1` 丢弃清单内内容继续，或输入 `2` 放弃本次转换。
- **有阻断问题**：不生成正式文件。全局结构错误或读取不完整不能通过“丢弃”绕过。
- **使用 `--prepare`**：只读取和预检，始终不生成正式文件，也不弹出丢弃确认。

不输入、输入其他内容或关闭提示不会默认同意丢弃。有不支持内容且运行环境不能交互时，保留预检记录，等待明确选择。一般提示保存在 `report.json` 中，当前没有强制逐项确认提示的机制。

预检后可使用同一快照继续；不会重新读取已经修改的飞书原文：

```bash
node src/cli.ts --resume "<RUN_DIR>"
```

非交互环境中，查看报告并决定丢弃后，可明确提交该次清单摘要：

```bash
node src/cli.ts --resume "<RUN_DIR>" --discard "<DIGEST>"
```

`<DIGEST>` 取自该任务 `report.json` 的 `digest`。它绑定快照、字段配置、转换结果和问题清单，不是对以后未知内容的授权。修改来源、字段或读取配置需要重新发起任务。代码更新导致结果或清单变化时，可对尚未完成的任务重新预检：

```bash
node src/cli.ts --resume "<RUN_DIR>" --prepare
```

重新预检后必须核对新清单。已取消的任务需要重新发起；已有 `strategy.json` 的任务不能继续或覆盖。飞书原文修改后，应重新输入文档地址建立任务，`--resume` 不会获取新版本。

| 退出码 | 含义 |
| --- | --- |
| `0` | 转换完成，或成功显示帮助 |
| `1` | 参数、读取、结构、资源校验或本地文件操作失败 |
| `2` | 仅完成预检、等待选择，或操作者取消；不代表已生成正式文件 |

## 3. 输出目录和文件用途

默认位置相对于启动命令时的目录，因此建议始终在项目根目录运行：

```text
 data/runs/conversion-<RUN_ID>/
 ├── strategy.json
 ├── assets/
 ├── snapshot.json
 ├── report.json
 ├── candidate.json
 ├── strategy.pending.json
 └── mmw-<RESOURCE_ID>-<REVISION>.bin
```

不同阶段不一定生成所有文件；很早就读取失败时，目录可能只有部分记录。指定 `--media-workdir` 后，`.bin` 位于指定的临时目录。

| 文件 | 用途 | 网站是否需要 |
| --- | --- | --- |
| `strategy.json` | 校验通过、必要选择完成后的正式攻略 JSON；不代表人工审核已通过 | 需要 |
| `assets/` | 下载并识别文件类型后的图片；JSON 使用相对路径引用 | 只需要 JSON 实际引用的图片 |
| `snapshot.json` | 飞书正文、版本、表格读取结果、图片引用和摘要，供复查及继续任务 | 不需要，内部留存 |
| `report.json` | 配置、清单摘要、不支持项、提示、阻断问题，以及流程状态和已记录的选择 | 不需要，内部留存 |
| `candidate.json` | 预检候选稿，可能仍有阻断问题或未确认的排除项 | 不需要，不能直接作为正式产物 |
| `strategy.pending.json` | 完整写入后用于生成正式文件的中间文件 | 不需要 |
| `mmw-…-<REVISION>.bin` | 飞书图片刚下载时的临时文件；数字部分是读取的文档版本号 | 不需要 |

`.bin` 的内容经签名检查后复制到 `assets/`，并使用识别出的扩展名。因此一次成功转换可能同时保留临时副本和最终图片；当前没有自动清理功能。三个攻略 JSON 在一次成功转换中也可能内容相同，它们的流程用途不同。

**不要直接修改 `strategy.pending.json`。** 当前实现用文件系统硬链接生成 `strategy.json`，两个名称可能指向同一份底层文件；修改中间文件可能同时改变正式文件。应回飞书修改后重新转换，也不要把手工编辑候选稿当成修改快照的方法。

网站只接收 `strategy.json` 及其实际引用的图片。整个任务目录含内部正文快照和记录，不应公开。默认 `data/` 已被 Git 忽略；使用自定义输出目录时需单独保证不提交内部数据。当前不提供自动打包或文件清理命令。

### 读懂转换报告

`unsupported` 是必须选择丢弃或取消的清单；`warnings` 是需要核对的展示或识别提示；`blockers` 是阻止正式输出的问题。每项包含问题代码、源块定位、位置说明和原因。

`status` 为 `pending` 时等待处理，`blocked` 表示阻断，`cancelled` 表示已取消，`publishing` 表示正在生成本地正式文件，`completed` 表示转换完成。这里的 `publishing` 不表示发布到网站。文件生成过程中异常退出可能留下中间状态，不能仅凭存在候选稿判断成功。

成功时 `decision` 为 `discard`（已确认排除）或 `no-exclusions`（无需排除），并记录选择时间和本地操作者标识。这是本地操作记录，不是已认证的飞书审核身份或人工审批记录。

## 4. 参数参考

| 参数 | 作用 |
| --- | --- |
| 文档地址 | 新建任务的必填位置参数 |
| `--duty-id`、`--duty-name` | 新建任务必填的副本短 ID、名称 |
| `--duty-type` | 可选副本业务类型 |
| `--profile legacy` | 默认；兼容明确的阶段前缀和用途标题，不把所有二级标题当作机制 |
| `--profile standard` | 用于明确按项目标题规范撰写的文档 |
| `--output` | 任务目录的父目录，默认 `data/runs`；不是最终 JSON 文件名 |
| `--prepare` | 只预检；新任务和未完成任务重新预检均可使用 |
| `--resume` | 继续现有快照；不能同时输入文档地址、字段或读取配置 |
| `--discard` | 与 `--resume` 一起提交具体清单摘要 |
| `--cli-path` | 已安装 CLI 可执行文件或 `run.js` 路径 |
| `--media-workdir` | 已存在的图片下载临时目录 |
| `--identity user`、`--identity bot` | CLI 身份，默认 `user`；机器人需要独立授权 |
| `--help` | 显示帮助 |

## 5. 支持范围与已知限制

已实现段落、标题、富文本颜色和强调、普通链接、列表、代码、图片、提示框、引用、分栏，以及已知 XML 结构的普通表格转换。简单嵌入电子表格补取单元格值、可获取样式和列宽；公式、隐藏区域、分组、复杂合并等未适配情况进入清单。支持范围取决于实际返回结构，Schema 能表达某种节点不代表所有飞书来源都有对应适配器。

当前读取层核对原始块分页覆盖范围及文档版本，表格独立检查版本，图片检查签名和摘要。它不保证跨文档、表格和资源取得原子快照。图片支持已识别的 PNG、JPEG、GIF、WebP 签名，下载后超过 50 MB 的图片暂不转换；该限制不是下载前的流量上限。

### 内容识别

- 明确的阶段、机制和用途标题可以生成导航、正文及连续的多套解法；来源块标识参与稳定 ID 生成。
- 普通段落里的“解法1”“解法2”“推荐”仍是原文，不会变成 `solution`、`multi_solution` 或默认解法，当前也不保证提示这些疑似方案。
- 没有正文的机制标题仍可能保留在导航中；空区块提示不是完整的“未写完机制”检查。阶段有正文但没有明确机制时，允许 `mechanics: []`。
- 没有新标题边界的末尾图组会归入当前区块，程序不判断图片究竟属于哪个机制。
- 重复阶段、已识别的模板占位、全局章节交错等会阻断；这不代表所有语义歧义都能自动发现。

这些限制需要操作者回看原文。补充疑似解法、空机制及图组归属诊断仍是后续工作，不应将“没有阻断问题”解释为语义全部正确。

### 不支持内容与展示差异

时间轴组件、音视频、附件、其他未适配组件和无法还原裁剪的图片进入选择清单。同步块尚未实现专门展开，当前按未知块报告。普通文字、表格或图片形式的时间轴仍可转换。

缩放、部分段落缩进、表格边框和行高等差异记录在报告中，网页渲染尚未实现。保留文字和资源不等于完整复刻飞书画面；Schema 校验也不证明战术内容正确。

## 6. 常见情况

| 情况 | 处理方式 |
| --- | --- |
| CLI 调用失败、超时或权限不足 | 检查已有 CLI 登录、身份、文档权限和路径；不要把凭据或原始敏感日志贴入聊天 |
| 图片下载失败，尤其 Windows／WSL 混用 | 检查 `--media-workdir` 是否是 CLI 能访问的现有本地目录 |
| 本地图片缺失或摘要不符 | 重新获取；不沿用旧确认、不用其他图片补同名路径 |
| 文档或表格版本变化 | 重新获取，不能将跨版本内容当作一致快照 |
| 未识别阶段、重复阶段或模板占位 | 回飞书修正标题；不要为绕过问题伪造阶段 |
| 只有候选稿，没有正式稿 | 查看退出码和报告；可能尚未确认、使用了 `--prepare` 或被阻断 |
| 清单摘要变化 | 对未完成任务重新预检并核对新清单，不能复用旧授权 |
| 已有正式产物 | 重新发起任务，保留原任务供追溯 |
| 报告停在 `publishing` | 检查正式文件、错误提示及文件系统硬链接能力；当前没有自动恢复此状态的命令 |

## 7. 开发验证

在项目根目录执行 `node tests/converter.test.ts` 或 `npm test`。Windows Node 与 WSL 混用时可执行：

```bash
node.exe "$(wslpath -w "$PWD/tests/converter.test.ts")"
```

测试覆盖转换、结构与关联校验、模拟飞书命令链、确认摘要变化及禁止覆盖。它不验证线上权限或实际网页渲染。当前没有独立类型检查、Lint、构建或开发服务器命令。

项目校验器支持仓库 Schema 当前使用的关键词，遇到未知关键词会拒绝运行。它不是供任意外部 Schema 使用的通用库；扩展契约时需同步检查校验实现。
