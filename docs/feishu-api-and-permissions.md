# 飞书 API 读取与基础权限方案

**状态：基础授权、本人任务审核与 API 读取已实现，真实飞书联调待完成。** 本文设计飞书 H5 网页应用的用户授权、直接调用官方 API 的文档读取，以及基础审核权限。当前新增了直接调用 API 的服务入口，见[H5 服务运行说明](review-server.md)；旧 CLI 入口继续保留。本文保留目标设计，实际支持范围以运行说明为准，尤其是嵌入电子表格、复杂富文本、原始快照网页下载和多实例运行尚未支持。

目标是让审核人员在网页中完成授权、提交文档、审核和导出，服务器无需安装飞书 CLI。服务器以发起人员的用户身份读取攻略，不改写飞书原文。攻略字段继续遵守[现有 JSON 契约](strategy-json-format.md)，读取方式变化不要求改变网站需要的字段。

## 1. 使用流程与职责

```text
审核人员打开飞书 H5 应用
  → 飞书授权登录 → 服务器确认组织、账号及审核角色
  → 提交攻略地址、副本 ID 和名称
  → 服务器使用该人员的用户凭证调用飞书 API
  → 保存原始文档块、表格和图片，形成固定快照
  → 转换预检，展示正文、警告和不支持项
  → 人工通过或驳回
  → 明确选择丢弃列出的不支持项，或放弃转换
  → 校验通过，保存 strategy.json 及引用图片
```

预检可以提前运行，以便审核人员知道哪些内容无法进入产物；正式导出必须在人工通过且必要的排除选择明确之后。初版仍审核全文，只在飞书修改正文，不提供区域审核、AI 审核或自动发布。

| 部分 | 职责 |
| --- | --- |
| H5 网页 | 展示授权入口、任务与审核内容；提交用户操作 |
| 授权服务 | 处理飞书授权回调、识别组织和用户、维护会话及用户凭证 |
| 权限服务 | 校验角色、账号状态、任务归属和当前文档访问能力 |
| 读取脚本模块 | 调用官方 API，读取正文和资源，记录缺失或失败 |
| 转换模块 | 将文档结构转换为攻略字段，生成诊断并执行现有校验 |
| 任务与文件存储 | 保存快照、审核决定、转换结果和操作记录 |

这里的“脚本”是服务器可调用的 TypeScript 模块，不需要审核人员运行命令。可使用 Node.js 自带的 `fetch`；是否使用官方 SDK 留到实施时确定。网页不接收应用密钥、飞书访问令牌或刷新令牌。

## 2. 三层权限分别判断

一次操作需同时满足适用的三层权限，不能用“已经登录”代替其他判断。

| 层次 | 判断内容 | 管理位置 |
| --- | --- | --- |
| 应用接口权限 | 应用已开通对应用户身份接口权限，用户也授予了所需范围 | 飞书开放平台及用户授权流程 |
| 飞书资源权限 | 当前用户可以读取这份文档，以及需要获取的图片、表格 | 飞书文档或知识库权限 |
| 系统业务权限 | 当前账号有效、属于允许组织、具备审核角色且可操作此任务 | 本系统服务器 |

后台凭证使用 `user_access_token`。不使用管理员的个人凭证替全组读取，也不在用户权限不足时自动切换为应用身份。应用可用范围限制入口，但服务器仍校验飞书返回的组织标识；不信任前端提交的姓名、组织或角色。

### 2.1 初版角色与任务范围（已确认）

| 角色 | 可执行操作 |
| --- | --- |
| 普通成员 | 登录、查看自身账号状态；尚不能创建或查看审核任务 |
| 审核人员 | 创建任务，查看自己的任务，执行通过／驳回、排除确认和导出 |
| 权限管理员 | 查看成员与角色、授予或撤销审核角色、停用账号、查看不含正文的管理记录 |

权限管理员与审核人员可兼任；管理员身份本身不赋予阅读所有攻略或代替他人审核的权利。成员以应用内的 `(tenant_key, open_id)` 标识，显示名称仅用于展示，不作为权限依据。

初版只处理本人发起的任务，不设置公共任务池、独立二审、自动转交或互相查看。审核人员可审核自己发起的任务；本系统不自动识别作者身份，也不增加禁止自审规则。

每次访问任务详情、正文、图片、原始快照、产物下载或执行决定时，服务端都检查角色与归属。猜中任务 ID 或图片地址不能绕过检查。无权访问的任务不返回标题、来源链接等元数据。

### 2.2 管理员如何产生与撤销权限

首位管理员由部署人员在服务器受控配置中指定其组织及用户标识，并在本人飞书登录后匹配；不允许“第一个登录的人自动成为管理员”。之后在网页中管理角色，变更记录操作者、对象、前后值和时间，不能移除最后一位有效管理员。

服务器逐次读取有效账号状态与角色，不长期信任会话内缓存的旧角色。撤销审核角色或停用账号后，阻止新操作，并让排队、运行中的任务在下一检查点停止，正式落盘前再次检查。退出网页会话与撤销飞书授权是不同操作：退出至少失效本系统会话；解除授权另外使对应凭证不可用并停止相关未完成读取任务。

## 3. H5 登录与用户授权

审核人员日常只操作网页；管理员仍需预先在飞书配置自建应用、网页地址、允许的回调地址、应用可用范围及必要接口权限。网页不能自行授予用户原本没有的文档权限。

采用一条明确的用户 OAuth 授权链路：

1. 服务端生成短时、一次性的授权事务，将随机 `state` 与浏览器会话绑定，记录允许的返回位置，并采用 PKCE S256。请求登录及当前读取所需的用户权限。
2. 网页跳转到飞书官方授权页面。拒绝授权时返回明确提示，不创建读取任务；飞书客户端中的免登体验不作为已取得全部文档权限的证据。
3. 回调由服务器校验 `state`、有效期及一次性使用状态，再交换凭证。授权码不写入访问日志；不接受任意回跳地址。
4. 使用凭证获取可信用户信息，检查允许的组织标识，再建立系统会话。普通成员不会因授权成功自动成为审核人员。
5. 网页仅持有本系统会话 Cookie，设置 HttpOnly、Secure 和适合实际回调方式的 SameSite；修改状态的请求另做 CSRF 防护。授权完成后清理浏览器地址中的授权码。

用户凭证在服务器加密保存，密钥放在环境变量或受控密钥文件中，不与数据库备份混放。凭证不进入 `snapshot.json`、`report.json`、日志或导出文件。

按接口实际返回的有效期管理凭证，不写死有效时长。若需要刷新令牌，按所选官方 OAuth 流程申请相应授权范围；缺少刷新能力时要求用户重新授权。按用户串行刷新，原子替换新凭证，防止并发刷新覆盖。授权撤销或刷新失败时暂停任务，不无限重试；用户重新授权后确认仍为原组织与用户，再继续或重新读取。

首次实现需固定同一套当前 OAuth 版本，不能混用旧免登、旧 OIDC 和新版 OAuth 的参数及响应。授权撤销事件可用于加快失效，但不能替代每次接口调用的错误处理。

## 4. 直接读取飞书文档

### 4.1 输入和输出

拟议模块入口：

```ts
readDocument({ documentUrl, actorId, taskId }): Promise<ReadResult>
```

`actorId` 来自经过验证的服务端会话，不能由网页随意指定。模块通过内部凭证服务获取令牌；输入不包含明文凭证。副本 ID、名称、类型和标题识别模式属于转换配置，单独保存在任务中，不影响飞书身份。

`ReadResult` 返回快照引用、资源清单和诊断，不直接返回“审核通过”。脚本可由后台任务调用；脱离网页运行时，也只能引用服务器已授权的用户与任务，不能绕过角色检查。

### 4.2 读取顺序

| 步骤 | 做什么 | 失败时如何处理 |
| --- | --- | --- |
| 校验输入 | 沿用 HTTPS 飞书 wiki/docx 链接白名单，解析标识，不抓取任意网页 | 非法地址直接拒绝 |
| 解析知识库链接 | wiki 链接通过节点接口取得真实对象类型和文档标识；docx 直接解析 | 无权限、不存在或目标非支持的 docx 时阻断 |
| 读取文档信息 | 获取标题、版本等，记录读取起始版本 | 身份或正文权限不足时暂停／阻断 |
| 读取正文块 | 分页获取文档块，按根节点和子节点引用重建顺序 | 缺页、重复块、循环引用、缺少被引用块时阻断 |
| 获取资源 | 下载图片；补取嵌入电子表格的必要数据及元信息 | 分别记录权限、网络、结构支持状态 |
| 核对一致性 | 再次核对文档版本；独立表格也核对其版本与数据范围 | 版本变化或无法确认完整性时不形成可审核快照 |
| 固定快照 | 写入原始数据、资源摘要和读取清单 | 完整写入后才将快照标为就绪 |

文档块 API 的 JSON 是读取输入，不使用纯文本接口代替富文本。节点顺序依据父子引用，不按分页返回顺序或标题数字排序。读取时尽可能指定固定文档版本；正文版本不等于所有外部资源的版本，不能声称获得跨资源的原子快照。

官方能力涉及文档元信息、文档块分页、知识库节点、素材下载和电子表格读取。电子表格原生接口能否提供当前转换所需的样式、列宽、公式标识及版本证据，须逐项验证；CLI 的 `+sheet-info`、`+cells-get` 是组合能力，不存在直接等名替换的保证。

### 4.3 错误分类与资源边界

| 情况 | 方案行为 |
| --- | --- |
| 令牌过期 | 在允许范围内刷新后重试一次；失败则等待重新授权 |
| 缺少接口权限 | 提示管理员配置或用户补充授权；不伪装成空文档 |
| 文档本身无权读取、缺页或版本变化 | 阻断整个读取，不允许靠“丢弃”继续 |
| 已定位的图片／表格无权获取 | 明确标为“资源权限不足”，允许补授权重读，或按现有规则明确排除／取消；不称为格式不支持 |
| 时间轴组件、音视频或未适配结构 | 保留块定位与可取得的原始信息，进入不支持清单，不尝试绕过权限或盲目下载 |
| 限流、超时、服务暂时不可用 | 有次数上限的退避重试，尊重接口返回的等待提示；耗尽后暂停，不能自动变成已同意丢弃 |

排除只能针对已确定边界的资源或内容块；无法界定缺失范围时整体阻断。无论哪种可排除问题，都沿用“列出位置与原因 → 明确丢弃或取消”的机制，不默认接受损失。

图片按官方素材下载要求携带必要的来源上下文，流式写入临时文件，限制大小、检查签名和摘要，完成后放入 `assets/`。仅向预设官方 API 主机发送授权头，不向任意链接或跨主机重定向转发令牌。原文里的外部链接默认只保留链接，不抓取目标内容。

## 5. 快照与转换器的衔接

保留 `snapshot.json + assets/` 的目录概念，但新快照增加独立的格式版本。当前快照的 `content` 是 CLI 生成的 XML 字符串，新快照不能直接冒充当前 `Snapshot` 类型。

| 拟议快照字段 | 用途 |
| --- | --- |
| `snapshot_version` | 内部快照版本，与攻略 `schema_version` 分开，建议新版本为 `2` |
| `reader` | 标记 `feishu-openapi` 及读取器版本 |
| `source` | 文档地址、节点／文档标识、标题、版本及获取时间 |
| `blocks` | 官方 API 返回的原始文档块，保留块 ID 和父子关系 |
| `sheets` | 表格原始数据、范围、版本证据和读取结果 |
| `images` | 块 ID、素材引用、本地相对路径、摘要及读取结果；图片字节仍放 `assets/` |
| `completeness` | 分页完成、关系校验、资源状态和版本核对证据 |

用户授权凭证单独存放。读取人及其组织归属、任务归属保存在任务记录中，快照不是权限凭证。

建议适配路线是“原始文档块 → 有序的内部正文节点 → 现有攻略转换规则”，不依赖 CLI 重新生成 XML。当前 `Node` 树可作为复用起点；需要显式适配文本样式、图片尺寸、表格、分栏和未知块，保留来源定位。不能将 API 原始字段直接塞进现有树并假设语义一致。

现有 XML 快照保留只读兼容入口，识别为旧格式后仍走旧解析路径；新旧快照都进入同一业务转换规则。最终 `strategy.json` 的字段与 Schema 保持不变。现有实现已支持新 API 快照使用内部节点，旧 CLI 快照继续通过原入口读取；网页暂不导入旧任务。

快照及图片固定后不覆盖修改。审核决定绑定 `snapshot_hash`；排除决定另绑定快照、转换配置、转换器版本及完整问题清单的摘要。重新读取、配置变化或规则变化使旧排除确认失效。内容改变必须重新审核；规则改变而原文未变时，至少重新预检和确认，不悄悄沿用旧结果。

## 6. 审核状态、访问检查和存储

### 6.1 状态分开记录

| 状态轴 | 建议值 |
| --- | --- |
| 读取 | `queued`、`reading`、`ready`、`waiting_authorization`、`failed` |
| 人工审核 | `pending`、`approved`、`rejected` |
| 转换 | `not_started`、`needs_confirmation`、`running`、`completed`、`cancelled`、`failed` |

读取未就绪不能批准；驳回不导出；取消转换不抹除人工审核结论。重新读取产生新的任务版本，审核回到待处理状态，旧记录保留。暂时获取不了权限时暂停相关操作，不把原有人工决定改成驳回。

通过／驳回和排除确认携带任务版本，由服务器核对；对重复点击返回原操作结果，对过期页面返回“内容或状态已变化，请刷新”。正式产物需要审核通过、当前权限有效、所有排除项已确认、无阻断问题且校验通过，并以不可覆盖方式保存。记录产物摘要及对应的审核版本。

### 6.2 本地快照也受权限限制

采用保守默认：重新打开任务正文、通过／驳回、导出或下载前，使用当前操作者的凭证检查原文访问能力；保留的独立表格和图片也按所需操作检查。不得用另一人的成功读取记录证明当前人有权限。

若某类资源没有合适的独立权限探测接口，可通过实际读取／下载检查；元信息可读不代表素材可下载。实现可在单次页面请求批次中复用检查结果，缓存上限待验证后确定；决定和下载必须重新检查，不依赖长期正向权限缓存。飞书暂不可用时阻止新访问，不能直接返回服务器缓存正文。

原文更新时，旧快照不被替换。批准前发现版本变化，要求重新获取并审核；已批准记录及产物仍对应旧版本，并标注来源版本，后续原文更新不改写既有批准。该设计无法撤回用户此前已下载的文件，也不能保证检查之后权限绝不变化；服务端在每个关键边界重新检查，发现撤销就停止继续提供内容。

`data/` 不作为静态网站目录公开。快照、图片及产物通过有鉴权的任务接口访问；涉及正文的响应禁止公共缓存，前端不把正文持久缓存为离线数据。原文 HTML、链接和样式需按展示白名单处理，不执行源文档脚本。

### 6.3 最小存储对象

初版使用 Node.js 内置 SQLite 保存身份与任务记录，文件继续保存在本地任务目录。数据库在服务启动时初始化，未对既有 CLI 数据执行迁移。

| 对象 | 最少保存的信息 |
| --- | --- |
| 成员与角色 | 组织标识、用户标识、显示名、角色、是否启用、角色版本 |
| 用户授权 | 用户关联、加密凭证、实际授权范围、到期时间、授权状态 |
| 网页会话 | 不透明会话标识的摘要、用户关联、有效期和失效状态 |
| 任务版本 | 归属用户、文档来源、副本配置、快照位置与摘要、状态、版本号 |
| 审核与排除决定 | 操作者、时间、决定、意见、快照摘要及清单摘要 |
| 产物 | 任务版本、文件位置、摘要、生成时间及排除结果 |
| 操作记录 | 操作者、动作、对象标识、结果、时间；不存凭证或正文 |

磁盘文件与数据库无法假装是同一事务：先写任务临时文件，核对成功后再发布引用；崩溃恢复时核对状态和文件摘要，不根据半成品自动认定完成。角色变更、批准和产物发布需有并发版本校验。保留期限、磁盘配额、备份与清理策略需在上线前确定，不默认永久保存或自动删除。

## 7. 拟议服务接口

下表为系统内部接口，不是飞书 API；已实现的运行限制见[服务说明](review-server.md)。

| 接口 | 用途与校验 |
| --- | --- |
| `GET /auth/feishu/start`、`GET /auth/feishu/callback` | 发起授权、校验回调并建立会话 |
| `GET /api/me` | 返回当前账号状态与角色，不返回飞书凭证 |
| `POST /api/logout` | 使当前系统会话失效 |
| `POST /api/tasks` | 审核角色提交来源与副本配置；身份由会话确定 |
| `GET /api/tasks/:id` | 先校验归属与角色，含正文的响应再检查飞书权限 |
| `POST /api/tasks/:id/refetch` | 建立新快照版本并重置该版本的审核状态 |
| `POST /api/tasks/:id/review` | 绑定任务版本及快照摘要，提交通过或驳回 |
| `POST /api/tasks/:id/conversion` | 确认具体排除清单并导出，或取消转换；无排除项也需明确导出操作 |
| `GET /api/tasks/:id/assets/:assetId` | 校验权限后提供清单内图片，不接受任意磁盘路径 |
| `GET /api/tasks/:id/export` | 校验后下载含正式 JSON 和引用图片的 tar 包，不暴露内部快照 |
| `GET /api/admin/members`、`PATCH /api/admin/members/:id` | 管理员查看成员并修改角色或停用状态 |

## 8. 实施顺序与验收条件

建议先完成用户授权和只读 API 读取验证，再接入转换，最后增加网页审核。保留当前 CLI 版本作为兼容入口，直到新读取器的真实样本验证完成；不在首次改造时删除旧任务。

实施至少需验证：

- 组织不符、普通成员、停用账号不能创建或操作审核任务；管理员不自动拥有正文权限。
- 授权拒绝、回调重放、错误 `state`、过期令牌、并发刷新和撤销授权均有明确结果。
- 用户 A 不能通过任务 ID、图片地址或下载接口访问用户 B 的快照；撤销角色后旧页面和后台任务不能继续导出。
- 有正文权限但无图片／表格权限时可准确定位缺失；分页不完整及读取中版本变化必须阻断。
- 用真实攻略对比旧 CLI 快照和新 API 快照，核对文本及顺序、富文本样式、图片摘要、表格内容和不支持清单，而非要求两份原始快照字节相同。
- 旧确认不能用于新快照、配置或清单；并发决定和重复导出不能覆盖正式结果。
- 网页真实展示可核对正文和排除项；Schema 或模拟测试通过不能代替真实权限与渲染验收。

## 9. 实施前需确认与验证的事项

已确认管理员与审核角色可兼任、审核人员仅处理本人任务，初版不设计独立二审和他人接手。全组任务池、转交及独立二审不属于当前实现范围。

技术上需验证：应用当前获批的用户身份权限范围；组织和用户信息字段；当前 OAuth 接入方式与刷新条件；原生表格接口的样式和版本覆盖；素材下载所需来源上下文；权限预检的接口组合与成本。本文未将这些接口在本组织中的真实可用性视为已经验证。

完整权限范围清单应在开发前按实际调用接口逐一列明并获得管理员配置，不能申请全部权限来掩盖缺项，也不能因为同组织就默认已授权。
