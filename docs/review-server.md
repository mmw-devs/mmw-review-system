# H5 审核服务运行说明

本服务为 MMW 组织内成员提供飞书授权、本人任务审核及 JSON 导出，是后续统一使用的入口。服务器直接调用飞书官方 API，无需安装飞书 CLI；旧代码和[命令行说明](converter-cli.md)仅保留作历史兼容参考。

本文是当前运行能力、配置、审核操作和验证边界的说明来源。平台介绍与作者规范通过链接引用这些事实；它们保留的目标设计不代表当前全部实现。攻略字段和关联约束仍以 [JSON 契约](strategy-json-format.md)及配套 Schema 为准。

**验证范围：已完成模拟 API 测试与本地浏览器操作验证，尚未完成真实飞书组织联调或生产部署。** 网页呈现的是可转换正文及排除清单，无法展示的内容应通过原文链接核对。此版本不包含独立二审、任务转交或公共任务池。

## 1. 环境和一次性配置

使用 Node.js 24 或以上，依赖其内置 HTTP、加密、SQLite 和 TypeScript 执行能力，不需要安装 npm 依赖。服务按单进程运行，不启用多实例或多进程共用数据库。

先由应用管理员在飞书开放平台配置自建网页应用：

- 设置网页入口、应用可用范围及对应可信域名。H5 走浏览器 OAuth 授权回调，不能只取得免登身份就跳过文档授权。
- 配置回调地址 `<REVIEW_ORIGIN>/auth/feishu/callback`，必须与服务配置一致。
- 开通用户身份下的文档、知识库读取和素材下载权限；需要刷新凭证时申请对应授权范围。
- 使用应用内用户标识 `open_id` 指定首位管理员；该用户首次登录时成为权限管理员，不自动获得审核角色，可在成员页面为自己勾选审核角色。

在项目根目录本地创建 `.env.local`，只在本机填写真实配置，不发到聊天、PR 或日志。文件已被 Git 忽略。以下仅是模板，尖括号需要替换：

```dotenv
FEISHU_APP_ID=<FEISHU_APP_ID>
FEISHU_APP_SECRET=<FEISHU_APP_SECRET>
FEISHU_TENANT_KEY=<ALLOWED_TENANT_KEY>
REVIEW_ADMIN_OPEN_ID=<INITIAL_ADMIN_OPEN_ID>
REVIEW_ORIGIN=https://<REVIEW_APP_DOMAIN>
REVIEW_ENCRYPTION_KEY=<BASE64_32_BYTE_RANDOM_KEY>
REVIEW_PORT=4325
REVIEW_DATA_DIR=data/review
FEISHU_USER_SCOPES="docx:document:readonly wiki:wiki:readonly drive:drive:readonly offline_access"
```

| 配置 | 含义 |
| --- | --- |
| `FEISHU_APP_ID`、`FEISHU_APP_SECRET` | 自建应用的标识及密钥；密钥仅用于服务端授权交换 |
| `FEISHU_TENANT_KEY` | 允许登录的飞书组织标识，不能用公司名称代替 |
| `REVIEW_ADMIN_OPEN_ID` | 首位权限管理员在此应用中的用户标识，不是用户名或手机号 |
| `REVIEW_ORIGIN` | 用户实际访问的完整站点源，不含路径和末尾斜杠；线上必须 HTTPS |
| `REVIEW_ENCRYPTION_KEY` | 32 字节随机密钥的 Base64 文本，用于加密本地飞书凭证；更换后原凭证无法解密，需重新授权 |
| `REVIEW_PORT` | 本机监听端口，默认 `4325` |
| `REVIEW_DATA_DIR` | 数据库与任务文件目录，不放到静态网站目录下；默认 `data/review` |
| `FEISHU_USER_SCOPES` | 空格分隔的用户授权范围；须在飞书后台开通，并按实际接口要求核对 |

上述 scope 是当前实现的候选组合，不代表已在本组织获批，也不保证是最新接口下最窄的可选权限。素材下载存在不同授权范围与文档下载策略；正式启用前应由管理员根据官方接口及实测收窄并确认。应用获得接口权限仍不能访问用户没有权限的文档。

可在项目根目录执行以下命令，仅将随机加密密钥写入本地环境文件，不在终端打印；若已有该配置则拒绝重复追加：

```bash
node -e 'const fs=require("node:fs"),crypto=require("node:crypto"),p=".env.local";const s=fs.existsSync(p)?fs.readFileSync(p,"utf8"):"";if(/^REVIEW_ENCRYPTION_KEY=/m.test(s))throw Error("已存在加密密钥配置，请勿覆盖");fs.appendFileSync(p,"\nREVIEW_ENCRYPTION_KEY="+crypto.randomBytes(32).toString("base64")+"\n",{mode:384});console.log("已写入本地密钥配置，未显示密钥")'
```

备份数据库时单独保护环境文件；凭证加密密钥不能与数据库公开或放入 Git。初次安装时的管理员选择只生效一次，之后通过网页管理角色，不能仅修改环境变量来绕过既有管理员控制。

## 2. 启动与使用

完成本地配置后，在项目根目录执行：

```bash
node --env-file=.env.local src/review-server.ts
```

也可执行 `npm start`。服务只监听 `127.0.0.1`。正式使用需由既有 HTTPS 反向代理转发，并遵守仓库部署规则；已提供[部署模板](../deploy/README.md)，默认关闭且未应用到服务器。本地浏览器验证可将源设置为 `http://127.0.0.1:4325`；飞书端是否接受该回调须单独核实，不能把本地模拟成功当作客户端内登录成功。

审核人员在页面中的操作顺序：

1. 使用飞书授权登录。普通成员初次登录后等待管理员授予审核角色。
2. 提交文档地址、副本 ID 和名称，选择标题识别模式，填写要求见下表。
3. 提交后自动显示导入进度；已完整读取的页面可提前阅读。也可在“我的任务”打开任务，按“副本基本信息”、P1、P1.5、P2 等页面查看正文。顶部导航和上一页／下一页切换页面，地址保存当前任务与页面，支持刷新和浏览器前进后退。整篇就绪后展示完整问题清单，必要时打开飞书原文。
4. 等整篇快照就绪后，对副本基本信息和每个 P 分别通过或驳回。至少一个 P 通过后，可选择取消转换；若要导出完整攻略，还需解决阻断问题并明确确认排除清单。仅副本基本信息通过不足以导出。其他页可保持待审核或驳回，页面明确列出未通过部分。不支持项不会默认勾选，导出不代表整篇审核通过。
5. 下载包含 `strategy.json` 与其引用图片的标准 tar 包。此包不含快照、授权凭证或内部审核记录，也不会自动发布网站。

| 页面字段 | 填写要求 |
| --- | --- |
| 飞书文档地址 | 从浏览器复制完整 HTTPS 地址；接受 `feishu.cn` 或其子域下的 `/wiki/<TOKEN>`、`/docx/<TOKEN>` |
| 副本 ID | 网站约定的副本短 ID，例如网站路径 `/07/m5s` 对应 `m5s`；使用小写字母、数字及分隔用的短横线或下划线，不含游戏版本目录或完整路径 |
| 副本名称 | 填写副本的可读名称，最长 200 字符；文档自身标题由系统另行读取，保存到 `duty.title` |
| 标题模式 | 默认“兼容现有攻略”；明确按作者规范组织标题的文档选择“规范模板” |

程序检查副本 ID 格式，不查询网站目录确认它存在。测试 ID 不代表已经完成网站映射；正式接入前需核对。可选副本类型由任务接口接收，当前页面没有该输入项。

读取和权限核对可能需要等待。导入期间，页面在一次读取结束后间隔约 2 秒自动查询进度；也可手动刷新。已闭合的 P 可提前阅读，图片尚未下载时显示加载占位；此时不能提交审核或导出。一次最多执行 4 个读取任务；单份正文上限为 24 MB／50,000 块。图片不设单张或单任务体积上限，但会占用服务器磁盘，需关注存储。任务列表只提供本人任务状态，不直接公开攻略标题；打开详情后才核对原文权限并显示内容。

“重新获取为新版本”创建一个关联的新任务，旧快照和决定保留，新任务所有页面重新审核，不自动沿用旧决定。升级前创建的任务继续整篇审核，重新获取后启用分 P 审核。当前实现不允许对已决定的同一快照反复改判；审核绑定导入时的固定快照，审批不要求当前 revision 与快照一致。需要审核新内容时重新获取为新任务，旧快照和决定保留。

## 3. 权限和授权失效

- 权限管理员可授予或撤销审核角色、设置管理员和停用成员，不能移除最后一位有效管理员。管理员身份不能查看他人正文。
- 每个任务只归发起人员使用。审核、预览、图片及下载接口均在服务端检查身份与归属；不支持接手。
- 获取任务详情、新请求一个 P、读取问题清单或图片、执行决定时，服务端重新检查原文正文的当前读取能力；图片字节从任务本地快照读取，导出时校验全部引用图片。回看会话内已缓存的 P 不重新请求正文；已加载内容可能在外部撤销权限后继续显示，后续请求发现权限失效时清空。没有跨请求的长期权限成功缓存。
- 飞书不可用、角色撤销或凭证失效会阻止继续读取和导出，不自动切换为应用身份。
- “退出”使当前网页会话失效；“断开读取授权”清除本系统保存的用户凭证。后者不声称已撤销飞书侧授权，完整撤销应在飞书授权管理中完成。
- 用户凭证采用 AES-256-GCM 加密保存，授权码、令牌和原始上游错误不写入日志。当前不接收飞书授权撤销事件，实际调用失败后要求重新授权。

## 4. 存储与恢复

```text
REVIEW_DATA_DIR/
├── review.sqlite          # 成员、加密凭证、会话、任务和操作记录
└── runs/<TASK_ID>/
    ├── snapshot.json      # v2 原始文档块、内部节点、资源和完整性记录
    ├── blocks/            # 分批保存的原始 API 分页
    ├── units/             # 按内容摘要保存的不可覆盖页面及问题清单
    ├── assets/            # 已下载图片
    ├── candidate.json     # 待确认转换结果
    ├── report.json        # 诊断及确认摘要
    ├── pending-*.json     # 完整写入后准备发布的中间文件
    └── strategy.json      # 人工通过且明确确认后生成的正式产物
```

任务和图片路径由服务器生成。`data/` 不经静态路由暴露，文件下载始终经过权限检查。正式文件通过硬链接发布，不覆盖旧产物，因此底层文件系统需要支持硬链接。正式文件和对应中间文件可能共享内容，不应手工修改。

服务重启后，不自动续跑中断的读取。页面会提示重新获取；若文件已经生成但数据库状态未完成提交，系统拒绝覆盖，需创建新版本处理。当前未实现任务自动清理、磁盘配额或备份调度，正式上线前需确定保留期限和存储运维方案。

## 5. API 读取与转换的能力边界

已接入 wiki/docx 解析、正文分页、父子引用完整性检查、读取前后版本核对和图片下载。导入通过根块的子孙块接口按先序分页读取，父子关系与实际顺序仍由块引用校验。分页可截断容器，预览仅使用连续且子树完整的顶层内容；只有发现下一阶段或到达文末后才发布对应 P。图片按批下载，当前阅读 P 中尚待处理的图片优先。正文请求在各批图片处理后继续，尚未读到的远处 P 不支持直接跳过游标获取。

所有批次固定到同一原文版本，每批与读取结束时核对版本；原文变化会使本次导入失败，已显示内容不能用于审核。飞书读取历史版本需要文档编辑权限，故仅有阅读权限时不能保证原文变更后继续读取旧版本。服务端对真实请求统一限速，并处理 HTTP 400／业务码 `99991400` 与 HTTP 429 限流。保留基本文字样式、标题、列表、代码、简单普通表格及分栏。未知或无法保留的内容保留来源块并进入排除清单，不静默删去。

H5 当前支持范围如下；旧 CLI 的历史支持情况不作为网页能力依据：

- **嵌入电子表格暂不转换。** 当前未完成原生接口对样式、列宽和版本的完整适配，整块进入明确排除清单。
- 合并单元格、带复杂样式的提示框、文字背景色、行内代码、提及和公式等尚未适配，受影响内容块进入清单。
- 文字颜色按已适配枚举映射为色系，并提示核对色值；普通表格列宽与外观、代码语言标识仍有展示差异。
- 时间轴组件、音视频、附件、未知嵌入内容和无法保留的图片变换仍须明确排除或取消。
- 素材下载直接调用官方接口；需要额外来源上下文的特殊资源可能被飞书拒绝，当前会报告而不绕过权限。
- 新快照提供内部节点供共用转换规则使用；网页不导入旧 CLI/XML 任务。
- 普通段落里的“解法1”“解法2”“推荐”保留为正文，不会自动生成解法选项；疑似方案提示尚未实现。
- 空机制标题可能保留在导航；没有明确标题边界的末尾图组会归入当前区块，需要人工核对。旧标题兼容分支不保证逐次报告级别偏差，页面不提供逐块配置映射。
- 图片缩放、部分段落缩进和表格边框等可能没有完整还原。

上述限制不应被描述为与飞书完全一致的网页预览。正式使用前，应选择实际攻略对照原文核验读取和展示结果，并验证组织权限与 H5 授权。

## 分 P 切分与审核边界

副本基本信息始终是首个审核页，包含副本名称、短 ID、可选类型、攻略须知和战前准备；这些内容不复制到每个 P。阶段页面只展示对应阶段正文，按原文顺序排列，不按编号重新排序。

`P1.5`、`P1.5阶段` 独立切分，内部标识为 `p1-5`，保留原始显示标题。规范模式的一级标题 `P1.5 · 阶段名称` 表示阶段，历史兼容模式的 `P1.5 · 机制名称` 表示该阶段下的机制，连续同阶段机制不会重复切分。转场不独立切分，留在当前 P；表格、分栏等容器内部标题不建立阶段边界。

审核接口沿用 `POST /api/tasks/:id/review`。新任务必须提交 `unitId`（`basic` 或阶段 ID）、`digest`、`snapshotHash`、`version`、`decision` 和 `comment`。服务端核对单元存在性、快照与规则摘要、任务版本，保存每页审核人、时间及意见，再汇总整篇状态。相同决定可重复提交；已决定的单元不能改判，正文修改后需重新获取。

导出的 `strategy.json` 仍是完整攻略，图片按引用去重。分 P 审核记录仅存于内部任务，不进入攻略 JSON，也不改变攻略 Schema。

## 页面与服务端的操作契约

任务详情及审核、转换操作响应由服务端返回 `actions`，统一说明当前可审核的单元以及能否导出、取消和下载。`actions.review` 按 `unitId` 保存结果，旧任务使用 `whole`；`actions.export`、`actions.cancel`、`actions.download` 分别保存对应操作的结果。每项包含 `allowed`，不可操作时可提供 `reason`。这些动作信息按当前状态计算，不另行保存到数据库。页面根据结果展示操作和原因，不自行组合审核状态来决定业务资格；请求进行中、缓存过期等页面状态仍可临时禁用提交。

`actions` 表示生成响应时的判断，不是长期授权。执行操作时，服务端仍重新核对身份、权限、任务版本和相关条件。错误响应包含供页面显示的中文 `error`、稳定的 `code` 和是否释放当前任务缓存的 `clearTask`；页面按这些字段处理错误，不从中文提示或 HTTP 状态猜测是否失去任务访问权限。


## 页面缓存与图片加载

浏览器首次仅获取任务概览和当前 P 正文，整篇就绪后另行获取完整问题清单。进入其他 P 时才请求对应正文与图片，最近访问的三页在会话内复用，草稿与阅读位置独立保留。切换页面会取消过期正文请求并忽略迟到响应；离开仍有图片请求的页面时释放该页请求。刷新浏览器或切换任务重新读取。退出、断开授权以及请求检测到权限失效时释放缓存，不写入浏览器持久存储。

首次读取任务和未缓存页面时显示加载动画，等待较久时提示仍在处理；手动刷新保留正文并显示更新状态。请求超时或失败提供重试入口。审核或转换成功后直接更新内存状态；状态冲突时重新读取，保留同一快照的意见草稿。刷新失败后仍可阅读缓存，但须刷新成功后才能再次提交。

图片显示失败独立于源图片拉取失败。失败时查询图片接口的具体错误，网络或临时服务异常最多自动重试两次，之后提供单图和本页失败图片重试。授权失效会清空任务，资源缺失或校验异常提示刷新或重新获取任务。图片显示失败不禁用“审核通过”，也不自动把图片加入排除清单。

导出后仍可审核尚未决定的 P；完整 JSON 内容不因后续审核状态变化而重写。旧任务继续要求整篇通过后导出。


## 渐进阅读接口与完整性

| 接口 | 返回内容 |
| --- | --- |
| `GET /api/tasks/:id` | 任务状态、导入进度、已可读的页面目录、各页内容摘要、问题数量及操作资格，不返回整篇正文 |
| `GET /api/tasks/:id/units/:unitId` | 当前页的正文及相关问题；`basic` 为基本信息，`p1-5` 等为阶段；旧任务使用 `whole` |
| `GET /api/tasks/:id/issues` | 整篇就绪后的完整问题清单，供核对与排除确认使用 |

导入中目录可能尚未完整。未闭合页面返回“此页尚未读取完整”，不是空正文。图片待下载、成功和已确认失败分别处理；待下载占位只存在于预览，不进入正式攻略或排除清单。后续失败或服务重启会停止提供未完成版本的正文；原始分批文件保留，不自动续跑或清理。

页面文件以内容摘要命名，索引保存在本地数据库。阅读时验证当前单元摘要，图片验证各自摘要；完整快照和报告的文件标识、大小、修改与变更时间发生变化时拒绝继续使用索引。审核及导出仍重新校验完整快照、转换规则和全文摘要。旧任务首次打开时经过原有全量检查，再生成分页索引；原快照及审核决定不被覆盖。

提前阅读不等于提前批准：正式审核仍绑定完整快照，导出仍包含整篇攻略，并要求完整结构校验和明确的排除确认。真实飞书的分页顺序、权限变化和大文档耗时仍需使用实际攻略联调，模拟测试不代表这些生产条件已经验收。
